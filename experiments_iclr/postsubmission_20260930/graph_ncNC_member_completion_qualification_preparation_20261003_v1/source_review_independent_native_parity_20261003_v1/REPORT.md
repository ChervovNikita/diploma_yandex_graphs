Three boundaries should accompany any later qualification statement:

1. **Corresponding native gradients are covered; added factor gradients lack an independent oracle.** Each of nine factorized linear maps adds r and s, for 18 additional parameter tensors (`prototype.py:79–88`). Their forward expression is differentiable and correct by inspection. `qualify.py:188–198` checks weight/bias and norms, not r/s derivatives. Current documentation limits its promise to “corresponding native” gradients (`SEMANTIC_MAPPING.md:21`); claiming independent coverage of every portable parameter would overstate the harness.
2. **Double-model native encoder parity is outside this gate.** Graph values, degrees and normalized coefficients are computed in float32 (`graph_ops.py:43–53`; `prototype.py:67–73`) before coefficient casting. The native correspondence fixture deliberately uses float32 (`qualify.py:159`; `DEPENDENCIES.json:15`). The float64 portable oracles do not establish native float64 GCN identity.
3. **Loss scaling is verified by source inspection.** The implementation has the correct native sum of two means, but the schedule test asserts only scalar finiteness and a single encoder call (`qualify.py:273–279`). It would not independently catch a scaling regression.
