Root owns allocation admission and execution. After the scientific supervisor
writes successful terminal `END.json` and `OUTCOMES.json`, copy

SHA256 values plus the three actual terminal `RESULT.json` hashes. Those RESULTs

On the authorized allocation, use the original project `.venv/bin/python`:

```text
<python> -B -u <E>/pilot_20261015_residual_only_private_bn_v1/selected_VALID_addition_v1/run.py
  --project-root <repository>
  --admission <actual-root-admission.json>
  --admission-sha256 <actual-admission-SHA256>
  --mode commands
```

The default `commands` mode verifies all three terminal fits and prints the
three exact unchanged collector argv arrays without starting children. Then
use the same invocation with `--mode collect`, with the sole authorized GPU
visible. It runs one collector at a time, at most 600 seconds each, and writes
START/OUTCOMES/END with each actual outcome, work, failure, wall and memory
record. A failure stops later collection and is preserved. Use a fresh output
for any separately reviewed later attempt.

After all three admitted collectors finish, use the same invocation with
`CUDA_VISIBLE_DEVICES=''` and `--mode analyze`. The analyzer writes
`RESULT.json` and `REPORT.md`; a failed analysis gate writes `GATE.json` with
the observed collection outcomes and produces no partial score summary.

The package does not assign terminal hashes, select new checkpoints or admit
itself. `PLAN.json` binds the finite three jobs, original source closure, CPU
qualification and completed control analysis. `MANIFEST.json` binds this
addition's own files. No live or partial selected state is an input authority.
