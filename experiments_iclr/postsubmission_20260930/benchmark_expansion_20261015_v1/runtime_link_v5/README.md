# Runtime link v5: selected mean bridge and finite engineering policy

This is a distinct successor of frozen runtime v4. The four producer files
`bookkeeping.py`, `common.py`, `controllers.py`, and `source_rng.py` are byte
identical. Removing the declared additions from `adapters.py` and `run_fit.py`
recovers the complete original text. Original method/native/policy sources,
existing jobs, launchers and checkpoints remain separate and immutable.

## Link source and export authority

The explicit link dispatcher now preserves the callback's outer extension
receipt and authenticates its method manifest and complete ingredient/native
source receipts. Native single-body link adapters without an extension retain
their existing path. The new bridge currently requires the explicit interaction
provider contract; unsupported extended providers fail instead of losing a mean.

`LinkSameCallMeanAdapter` delegates native TRAIN and VALID to the existing
adapter. It reads the provider's zero-forward `selected_mean_sidecar`, checks
all 60,084 positive and 100,000 negative endpoints/IDs/labels in native order,
actual/mean tensors and summaries, update/epoch clocks, role and closed TEST.
Every TRAIN/restore invalidates the wrapper's validation authority. Source
cache invalidation and older validation serials also reject export.

The finalizer binds the exact selected payload immediately after loading it.
The bridge checks exact restored native state against that payload, immutable
JOB, selected epoch, checkpoint byte receipt, runtime, explicit link policy,
outer callback/extension, provider manifest and native/ingredient dependency
receipts. It emits actual and mean from the same selected VALID call, with no
additional native inference and no change to which metric selects the state.
This binding is distinct from numerical comparison of repeated inference.

## Finite engineering mode

The added `cpu_link_engineering_v1` mode requires hidden CUDA, an explicit
engineering-only link JOB, <=2 epochs, <=34 optimizer transitions, matching
minimum/maximum epoch bounds and no TRAIN diagnostic. The source epoch layout
must fit the declared cap. `OptimizerObserver` refuses another transition
before exceeding the cap. Existing node/OGB CPU mode and production dispatch
remain unchanged; engineering-only results on either device are labeled as
engineering work.

`engineering_link_policy.py` is separately pinned in a lifecycle JOB. It delegates
native settings/split/source validation to unchanged `link_policy_v1`, then
explicitly declares NCNC conditional-J, two full epochs, minimum2, patience1,
full VALID Hits@50, strict improvement and first ties. It does not claim the
production1000/100/50 matched schedule or paper reproduction. Production JOBs
continue to pin the original production link policy.
