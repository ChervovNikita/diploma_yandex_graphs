# Reuse actual functional evidence with explicit applicability

The source successor does not ask for 6,460 new smoke trainings. It requires a finite reviewed binding for every frozen task, and permits one genuine functional witness to support several tasks only when the applicability statement explains the unchanged code/settings/data/provider behavior. Evidence and applicability are separate fields. A saved dormant qualification block is an uncompleted binding, not an observed scientific failure.

The binding map schema is `allocation-server51-reviewed-task-bindings-v1`, with `unadmitted_release`, exact complete `tasks` mapping, and `source_files` needed by the bindings. Each task binding retains `execution`, `resources`, `measured_cost`, and `gates`. Gates remain:

| Gate | Evidence that may be reused after a source comparison | Genuinely destination-specific part |
| --- | --- | --- |
| source_context | Exact frozen callbacks/backbone/controller sources; canonical-to-execution reconstruction | Actual synchronized source bytes and host-local entrypoint/descriptor |
| provider_split_evaluator | Existing official provider/split/evaluator identity and full-role witness | Actual data bytes, same split/order and evaluator on destination |
| native_epoch_controller | Completed source/full-epoch lifecycle for unchanged driver/settings | Explicit applicability to the retained schedule/controller; no invented completed training |
| selected_export_resume_rng | Completed fresh selected reload/resume/export witness | Correct execution job/producer identity; a distinct composed-producer witness if prior identity is insufficient |
| mature_target_resource | Existing representative mature workload/cost envelope with applicability | Exact worker UUID, execution job hash, effective cgroup paths, CPU/RAM/VRAM/disk envelope and pair compatibility |
| reporting_statistics_access | Genuine scalar observer/selected producer and fixed comparison registry | This host's projected descriptor, actual producer and scorer manifest; V3 BUDDY replay remains pending until performed |
| source_reference_policy_or_matched_controller | Frozen source-reference vs matched-controller distinction | Same canonical track and unchanged execution policy |
| campaign_scope_bridge | Frozen method roster, native controls, GNNM baseline and I4/body0 reuse | Exact new source closure, ownership, output namespace, host release and explicit full-campaign GO |

Every gate JSON passed to `admit_release.py` must contain `status=PASS`, the exact `task_id`, canonical `science_contract_hash`, nonempty `applicability`, and an explicit nonempty list of pinned `witnesses`. Witness bytes are checked. The runtime launch retains the inherited additional resource/interpreter/worker/GO checks. A root review of applicability remains necessary; schema PASS alone cannot establish that a witness supports a scientific claim.

Current known evidence: the 24-fit PubMed pilot remains live with its own immutable producer; server51 already has native and structured-residual lifecycle witnesses. Those do not automatically grant this new composed runtime qualification. The root's BUDDY replay/reporting agent and resource-envelope agent supply the applicable receipts. No missing receipt is converted to PASS in this package. `admit_release.py` keeps `human_GO=false` even after a complete reviewed gate map is bound.
