# Queued NCN and BUDDY lifecycle retarget to portablev3

Source-only prelaunch successors of the already queued NCN direct conditional
and BUDDY input plus conditional lifecycle checks. Original JOB bytes, native
recipe, callbacks/extensions, policy, seed/split/body, work limits and observer
remain unchanged. The authentic old engineering policy module stays explicitly
bound at its original path. Current runtime is
`portable_dispatcher_v3/runtime_link`; the driver calls the exact portable
host/root/descriptor guards before Torch import and verifies module custody.

Native work remains two full epochs per case: NCN 34 optimizer maps and
BUDDY 3170 maps, with each original finite selection/export/restore lifecycle.
There are no new methods, seeds, fits beyond those queued, TEST calls or
checkpoint-binding rewrites. Any new selected binding is emitted by the real
current runtime during that admitted execution. No old checkpoint is relabeled.

The original drivers/plans are preserved. Fresh outputs and attempt claims use
a portablev3 namespace. Preflight refuses when the original queue already has
an attempt claim/output, preventing a silent duplicate. Existing physical GPU,
peer growth, host/disk, source/publication and timeout admission gates remain.
Current resource admission is mandatory; templates are not permission and do
not authorize a third CUDA worker. Root owns execution and scheduling.

`SOURCE_CHECKS.json` covers byte-identical JOBs/cases, unchanged work, current
source routing/guards and free names only. No model/data/state/GPU/TEST or
remote execution occurred in this preparation. The exports will supply current
selected states for the separately bounded VALID-serving qualification; this
retarget alone does not qualify final serving or campaign readiness.
