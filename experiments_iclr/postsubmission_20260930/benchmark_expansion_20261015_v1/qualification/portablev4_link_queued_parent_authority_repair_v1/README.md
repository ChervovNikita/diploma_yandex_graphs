# Finite queued link parent-authority repair

Concrete successor of `portablev3_link_queued_lifecycle_cacheaware_v1`, using `portable_runtime_authority_v4`. This is a source-only package; the included templates are not admissions. Root reviews and publishes both packages, binds current resource evidence and peer PID/start-time/growth envelopes, and launches only when the existing two-worker limit permits.

## Preserved work

Both JOB files, CASES, CACHE_POLICY and SOURCE_JOB_PROVENANCE are byte-identical to the predecessor. The native lifecycle body after Torch import and the entire cache-aware preflight function are unchanged. NCN remains bounded at 34 optimizer attempts; BUDDY at 3,170, with the same two TRAIN epochs, four VALID calls, construction/export/resume bounds, no TEST and no automatic retries. No new case or fit is introduced.

## Authority and custody

Both pinned compiler parent JSONs are direct source-closure entries. Support validates the current JOB schema and actual parent bytes/canonical hash before launching a child; the child repeats that validation before Torch. The new runtime manifest is pinned by support, closure, retarget metadata and both admission templates.

NCN admission requires the exact repair ID, prior failed publication/observation/claim/result, and distinct fixed output/claim from the runtime NCN contract. The helper verifies the actual preserved child terminal, claim, JOB and source pins, the exact classifier ValueError, no Torch import and all zero native-work counters. The prior child did start and incur process costs. All predecessor evidence remains untouched. The new permanent claim uses exclusive creation; no reset or generic retry is provided. Its repair identity and verified prior lineage are recorded in supervisor, claim and child result.

BUDDY keeps `portablev3_BUDDY_queued_lifecycle_attempt01` and `portablev3_link_queued_BUDDY_ATTEMPT_CLAIM.json`. It remains the original unexecuted logical queued case. Its admission rejects NCN repair fields.

## Root handoff

1. Review `DELTA.diff.txt`, runtime `DELTA.diff.txt`, both source reviews and check results. Stage and publish the two new package directories plus the already saved `NCN_LIFECYCLE_OBSERVATION_17.json` if not already published. Preserve all predecessor package bytes and claims/results.
2. On the correctly guarded allocation, verify the two frozen manifests and pinned parent/previous-failure files. The runtime contract expects the original child RESULT and claim at their unchanged remote paths.
3. Copy the appropriate new admission template to a fresh root admission file; fill the new driver manifest SHA, actual publication commit, current peer/resource evidence, and template/published flags. Keep all fixed output/claim/JOB/limits/runtime/repair fields. No admission is included here.
4. With an available compatible worker slot, run the new supervisor using the qualified `.venv/bin/python -B -u`, `CUDA_VISIBLE_DEVICES=0`, the exact template output, and the reviewed admission path. A preflight or failure does not authorize an automatic retry.

Local checks: `python3 -B check_retarget.py` from this directory. The 17 checks are source/JSON checks, not an allocation execution. The runtime package separately records 42 authority checks. Root still performs actual guarded metadata admission and any authorized native execution.
