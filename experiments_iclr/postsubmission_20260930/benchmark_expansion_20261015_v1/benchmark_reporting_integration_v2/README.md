# Compiler4 reporting integration — frozen source handoff

This successor connects the accepted reporter to actual compiler4 and
dispatcher4 identities. It performs no training, tensor deserialization,
prediction reconstruction, TEST evaluation or Git operation. Publication and
native/resource/GO admission remain root responsibilities.

## Runnable path

From the allocation package directory, with ordinary existing Python:

```sh
python3 -B build_registry.py --output new_registry_directory
python3 -B collect_campaign.py \
  --registry-index generated_v1/INDEX.json \
  --output new_report_directory
```

Both commands enforce the literal allocation host and sole GPU UUID before
project reads. They import no model or tensor library. The collector imports
NumPy through the already accepted reporter only when a complete ten-cohort
contrast is actually eligible for its descriptive interval. It preserves exact
fit/cohort/control identities, all missing/capped statuses and attempt costs.

For a future admitted physical fit, `runtime_entry.py` uses its exact registry
profile, descriptor and underlying runtime source. It calls the existing
`run_fit.run` once with the original job/output/resume arguments. The profile
selects current v4 node/molecular or v9 link sources. It wraps only the existing
atomic export writer and records invocation results. It does not alter jobs,
parameters, payloads, seeds, RNG, forwards, gradients, selection or serialization.
Its guard accepts visibility `0` or the exact sole authorized allocation UUID,
as used by the portable backend, while retaining the hostname/sole-UUID check
before project reads. The underlying v4/v9 allocation guard verifies the same
host and physical GPU and does not reject UUID visibility. No77 host adaptation
is included in this allocation-only entrypoint.

For I4, the same entrypoint calls the existing aggregator on the four exact
selected exports. Its observer reads scalar metrics/loss/member authorities
from the existing bank payload and records source/receipt/cost metadata. The
original aggregator performs its existing tensor loading/aggregation; the
observer adds none. The collector verifies exact four-body/M1 identity and
only grants aggregate binding evidence when all common component authorities
and the actual scalar export/source witness agree.

`backend_bridge.py:ObservedArgvTransform` is a pure callable:
`transform(task, output, checkpoint, states, original_argv) -> argv`. The
resource-reserving backend calls it inside its existing reservation transaction,
then performs its own unchanged Popen and ownership commit. The transform has
no `start` override, Popen, reservation, process or lease ownership. It must not
replace or bypass the resource-owning backend. Engine queues, claims, leases,
scientific contracts, dependencies, worker limits and GO gates remain unchanged.
Adoption requires root review and an explicit successor dispatcher binding;
**the active dispatcher was not modified**.

## Existing selected-export observer API

`observe_exports.py` is frozen at
`2a992dcf68f3b229f001f88779acb061036c0d1c974ffab613f1e3c1f588ff9a`.
The finite9 qualifier owner has attached this exact source to its unchanged
native lifecycle work:

```python
with observe(run_fit, job, fresh_reporting_folder, binding_spec=None) as obs:
    result = run_fit.run(job, root, output, resume)
    obs.record_invocation(result, "invocation_label")
```

One observer can enclose all three same-job lifecycle invocations. The owner
expects the two already-required selected exports and three invocation rows,
with no extra TRAIN, VALID, model construction or replay. That native check is
**pending root launch**; this handoff does not claim it passed.

`binding_spec=None` intentionally emits scalar/cost evidence with an explicit
missing campaign-binding reason. It cannot turn engineering data into the
6,190-row benchmark or support a complete-preset interval. Production profiles
contain exact job hashes and source/data/evaluator receipts; verified bindings
are emitted only with those profiles. Same-bank means come from the existing
selected export's actual authenticated mean sidecar, never reconstructed from
logits by this metadata collector.

## Costs, failures and remaining admission

Every supplied invocation retains its status, own wall, optimizer attempts/
completed counts, resume/finalization flags and process memory. The observer
also records its context elapsed wall. The collector labels the difference
from summed native invocation wall as context overhead, including verification,
serialization and possible owner gaps; it is not called pure preprocessing.
Every existing RESULT/history JSON attempt is retained even when an observer
also exists. Current observer receipts do not provide a guaranteed common UTC
attempt identity, so possible overlaps retain their recorded native wall and
work values but are not added twice to the numeric sum; attribution/uncovered
historical cost stays explicitly unknown. Unrecorded crashed work is never zero
by inference. Diagnostic rows and I4 exports add zero physical fits and refer
to their existing body costs. `REPAIR_CHECKS.json` covers the concrete mixed
history case and verifies the transform has no process-start ownership. The
initial all-missing collection preceded that cost-merge repair; it exercised no
history branch and is preserved as its actual scoped receipt.

No campaign execution or native observer test was added. The accepted nine
metadata checks were not repeated. The only new executed integration work was
the real compiler registry build and all-missing campaign collection. Current
source/native qualification and resource/GO gates still apply. The finite9
existing lifecycle will provide the first native selected-sidecar witness;

node/molecular studies need no duplicate training or repeated lifecycle for
