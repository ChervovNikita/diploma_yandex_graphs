# Expanded physical-fit descriptor compiler v1

This package accounts for the proposed **6,460 physical fit intentions** from 27 native presets: 270 separate source-reference native fits, 1,080 matched native body fits, and 5,110 shared-method fits. It prepares source-bound JSON only. It grants no scientific launch, resource admission, runtime lifecycle qualification, or full-campaign GO.

## Immutable inputs and outputs

`REGISTRY_v1.json` freezes the 511 method/preset mappings from the predecessor binding audit, with explicit later frozen ports and actual function aliases. The portable input methods explicitly supply rank cap 8 and the fixed dimension-aware frame policy. Molecular geometry preserves its exact allowed settings and pins its molecular manifest, helper release manifest and direct dependency hashes. The native settings rows remain complete in each expanded contract.

The compiler authenticates the original PLAN, ROSTER, native snapshot and smoke manifest, then reads and verifies the 2,480 predecessor JSON descriptors from `job_binding_preparation_v1/generated_v2` on the guarded allocation. Every predecessor physical fit ID and source-plan contract hash is retained. The global half-pool predecessor is a single physical fit with scientific alias `aggregation_mean_globalJ_v1`; a binding migration is explicit in the new descriptor. Newly added fits have an explicit predecessor template pointer and their own expanded contract; they are not represented as old PLAN jobs.

Full fit and blocked-intention records stay in a fresh allocation directory. Compact receipts/index metadata may be copied locally. Existing registry and output generations are never overwritten.

## Ownership and controls

The source-reference M1 is its own training track. The main M1 reuses exactly native I4 body 0. I4 owns four distinct fit IDs, native optimizers and selectors, with seeds `cohort_seed + [0,100003,200003,300007]`. The expected logical bank count is 5,920. All shared controls resolve within the same native preset/split/cohort. The selected-bank fixed-mean control is a diagnostic on the same selected fit with zero extra fits and no selection change.

The predecessor's 540 statistical/evaluate jobs are retained as history. New expanded statistical decisions are not invented here; their prospective protocol remains pending.

## Source and context honesty

Missing native BUDDY interaction sources and unsupported seed contexts are blocked, indexed fit intentions with no runtime descriptor. The authenticated BUDDY C6/responsibility context and private-BN context bind seed 0 only. Other seeds never receive that cached context. BUDDY C3 uses its actual source-supported manifest-only interface for all proposed source seeds, with no optional seed-0 engineering cache supplied.

The runtime validator is imported from the pinned runtime package only to call `validate_job`. Callback/transform names are checked with AST; model callbacks, transforms, adapters, numerical libraries and models are never imported or constructed. Runtime v4 lacks a fully bound link selected-mean/selected-state lifecycle and has outer extension/dependency authority gaps. Every link descriptor marks the successor as required. Source readiness and metadata validation do not establish that lifecycle, full epochs, convergence, CUDA, provider completeness or serving qualification.

Inherited data-role receipts are copied from predecessor JSON. This compiler never refreshes those hashes and never opens a dataset, tensor, model, selected state, prediction or TEST provider. No resource assignment is inferred from historical worker strings. `cuda:0` is a descriptor target only.

## Operation

Use only the expansion's reviewed `remote_control.py` transport, with its literal scientific destination and hostname/GPU-UUID guard. `transport.py` stages only this package's explicitly listed files; it never invokes broad `upload()`.

1. Run `python3 -B build_registry.py --output REGISTRY_v1.json` locally once to freeze reviewed source bytes.
2. Stage the new package through `python3 -B transport.py stage`.
3. Run `python3 -B transport.py compile --output-name generated_v1 --registry REGISTRY_v1.json`.
4. Retrieve compact metadata through `python3 -B transport.py collect --output-name generated_v1`.

For future authentic bindings, use a fresh explicit supplement with schema `expanded-binding-explicit-supplement-v1` and complete replacement `entries`, then `build_registry.py --output REGISTRY_v2.json --supplement PATH`. Each entry must state callback/transform exports, manifest/settings, base/runtime procedure, native preset/method ID and supported seed scope. New source bytes are authenticated; no fallback method or context is invented. A separately reviewed new runtime can instead be pinned in a fresh complete registry. Compile into `generated_v2` or another fresh output. Preserve v1 and every ancestor.

No command here launches fits, creates models, performs GPU compute, scores TEST, accesses server77, installs software, or publishes Git changes.
