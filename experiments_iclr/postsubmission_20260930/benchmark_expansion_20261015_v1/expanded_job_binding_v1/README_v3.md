# BUDDY production source overlay v3

This source and metadata successor retains all 6,460 physical fit intentions,
2,480 ancestor IDs/contracts, native settings, source-reference versus matched
controllers, M1/body0 reuse, I4 membership and scientific method definitions.
It does not admit the campaign or attach production runtime/resource/GO gates.

Ten BUDDY method bindings move from seed-0 context callbacks to the frozen
production-native provider: two responsibility, three aggregation, four
interaction recipes and private BN. One hundred fresh descriptors replace ten
seed-0 bindings and close ninety source-context blocks. The other 6,360
descriptor files are reused by authenticated receipt. Old registries, outputs,
blocked records and descriptors remain unchanged.

## Evidence scope

The accepted root receipt records one actual seed-1 production-provider
`interaction_input_conditionalJ` CPU check: two optimizer updates, three whole
VALID calls, two constructions and 32 native forwards, in 111.36 seconds.
The other recipes retain recorded AST/byte equivalence for unchanged objectives,
backward/Adam/BN/factor functions. They are not described as individually
executed on the new provider or at all ten seeds. The provider has no seed-0
oracle injection; the runtime owns actual seed initialization before native
construction. No duplicate per-seed context tensors are created.

This closes the missing **source/context** bindings. BUDDY whole native epochs,
actual selected-runtime/export/resume, callback protocol/device coverage outside
the representative check, measured resources and explicit campaign GO remain
unqualified. The separately passed NCNC v6 lifecycle is not transferred to
BUDDY. Metadata validation is not runtime qualification.

## Custody and compilation

`OVERLAY_v3.json` pins the three production source packages, compact provider,
source reviews, accepted representative receipt and underlying scalar result.
`compile_overlay_v3.py` checks the literal allocation hostname and sole UUID
before project access, then authenticates the parent v2 generation and source
receipt chain. It imports only metadata validators; Torch/NumPy/PyG/OGB imports,
tensors, native calls and TEST are forbidden.

The compiler writes only fresh `generated_v3`; it never overwrites a prior
output. It independently preserves scientific contracts except their explicit
source-registry/binding hashes, revalidates 100 descriptors, authenticates the
6,360 reused descriptors, and retains all logical-bank/control fit IDs.
Full descriptors remain on the allocation. Only compact JSON summaries,
verification and receipts are collected locally through the reviewed
`remote_control.py` guard. No native work or Git operation is performed here.
