# Dependency reporting repair, 24 October 2026

The first repair admitted one BUDDY README. Two subsequent allocation jobs
finished training and then failed because their genuine source closures included
other documentation. Restricting provenance validation by filename extension
was wrong. Source dependency bytes are read for hashing; they are not executed.

This additive successor verifies every declared runtime dependency as a canonical
regular file confined to the project with its exact observed SHA256. All frozen
job, runtime identity, helper binding, source manifest and reporting structural
checks remain active. All frozen files remain unchanged. The producer explicitly
records this repair. It covers documentation, metadata and source data extensions
without treating any suffix as execution authorization.

`audit_recovery.py --plan PLAN --output NEW_CONFIG` requires a stopped queue,
checks each failed attempt has only the known reporting error and already reached
patience, CPU-loads its own recovery/selection/export checkpoints, verifies job
identity and finite VALID logits, and performs the repaired reporting preflight.
The resulting immutable config pins the exact failures and original artifacts.
No TEST data is opened and no optimizer step is taken by the audit.

`activate_recovery.py --source-sha256 SHA --config CONFIG --config-sha256 SHA`
restarts only the same already-dead tmux pane, with no kill or signal. It requires
an unowned supervisor lock and unchanged global all-fit smoke release. Recovery
preserves mutable previous outputs and resumes finalization only. The worker
requires zero new epochs/optimizer transitions and unchanged selected checkpoint.
All later new fits retain the existing native arguments, resource admission,
maximum two jobs per GPU and frozen assignments. An unknown failure still stops
for investigation. Allocation and server51 workers are supported; each config is
bound to its worker and frozen plan. Active jobs are never interrupted.

Before collection, the collector must authenticate each original witness version;
v1 sidecars retain their original producer receipts. Do not replace old sidecar
receipts with v2. The queue-aware collector successor handles this separately.
