# PubMed/Cheb production cost probe

Source prepared for root review and resource admission. No native execution was performed during preparation. This package does not admit a pilot or the24-fit study.

## Fixed scope

One invocation selects exactly one of `M1`, `G0`, `uniform`, or `structured`, at seed101 and literal source split0. It constructs one cold adapter, performs two production `train_epoch()` calls and two whole original VALID calls, then exits. There is no selector, TEST evaluation, checkpoint save/restore, extra parity forward, gradient comparison, second model, queue or automatic retry.

`NATIVE_BUILDER.json` is an exact copy of the transfer driver's `SPEC.json.native_builder_spec`. Native M1 is body0 and G0 is original `gnnm_boundary_native`, generated by the original `runtime/run_pilot.py:build_jobs`. Residual jobs come from the exact frozen `pubmed_cheb_residual_composition_v1` descriptor/transform (manifest `1c5d3669cec6681bbfbda045a9497805805c287ab3e03b4aca5aa65c0e3cf0dc`). All four seed101 descriptors were compared with `pubmed_cheb_transfer_driver_v1/study.py:jobs`; allocation job hashes are in `SOURCE_CHECKS.json`.

The original source recipe, preprocessing, full graph, seven Cheb tokens, all11829 TRAIN records,3943 VALID records, source Adam groups and matched-controller metadata remain in the descriptor. The controller is never run. CPU execution changes only the engineering device field after validating the planned CUDA job. The original adapters, training code and residual transform are reused directly.

## Measurements

- Separate constructor, update1, VALID1, update2 and VALID2 wall times. Successful CUDA stages synchronize immediately before and after the timed operation. The two update measurements must remain separate; two updates do not establish steady-state epoch cost.
- Native module forward attempts and completions, including activation-checkpoint recomputation. Nonreentrant checkpoint early stopping can leave an attempted native forward without its outer completion hook. These are measured invocation counts, not FLOPs.
- Actual `autograd.backward` and `autograd.grad` attempts/completions, plus original `OptimizerObserver` Adam attempts/completions. The wrappers call the original operation once and add no derivatives. Expected production reverse calls are2 total for M1/G0 and4 total for either residual arm; Adam transitions are2 for every arm.
- One-process peak RSS and CUDA allocated/reserved peaks covering construction and both updates/VALID calls. No model/parameter snapshots are made for comparison.
- Byte proxies from already-returned VALID tensors and live model/Adam tensors. No checkpoint or prediction tensor file is written, and these proxies exclude serialization/container overhead and are not claimed as full checkpoint sizes.

Output contains `JOB.json` (the canonical planned CUDA descriptor) and incrementally saved `RESULT.json` (actual device, stage times/work, failures and memory). Stage timings exclude report writes and subsequent identity/support checks. The invocation wall time includes source/data hashing and setup. Failed stages are marked incomplete; their wall times are not guaranteed to include all asynchronously launched CUDA work. All failures require review; there is no automatic retry.

## Admission and finite bounds

Root must first verify the literal allocation route and admit isolated resources. The CLI requires `--root-resource-admitted` to acknowledge that completed external check; the flag itself does not perform resource admission. Run only through the original allocation repository virtualenv on hostname `anogena-2-0` with sole GPU UUID `GPU-44039938-fd82-41d2-fefd-de71514e2fac`. The script checks the route before project reads. Root must retain an outer process deadline: the internal900-second Python signal alarm is not a substitute for a hard supervisor deadline when native code is unresponsive.

Required arguments are `--project-root`, `--manifest-sha256`, `--variant`, `--device`, `--output`, and `--root-resource-admitted`. Output must be fresh and contained in the repository. Use `CUDA_VISIBLE_DEVICES=0` (or the literal UUID) with `--device cuda:0`; CPU engineering requires `CUDA_VISIBLE_DEVICES=` and `--device cpu`. Both use two CPU threads. Do not repeat the already-passed CPU numerical qualifiers merely to exercise this source.

Bounds per invocation: one constructor, two complete TRAIN updates, two complete VALID calls, two or four production reverse calls, two Adam transitions,64 native forward attempts including recomputation, and900 seconds by the internal alarm. Parent resource admission and an outer timeout remain required. No scientific checkpoint initialization, score conclusion, steady-state extrapolation or fit admission follows from a successful probe.

## Preparation checks

Only stdlib parsing/compilation, original descriptor schema validation, exact descriptor comparison and source hashing were performed. Numerical-library imports were blocked during checks; no tensor/model/data execution, SSH, remote operation or Git operation occurred. `SOURCES.json` pins the direct producer/builder dependencies; the frozen composition's own source verifier checks its complete retained source closure and data pins are checked as bytes before runtime construction.
