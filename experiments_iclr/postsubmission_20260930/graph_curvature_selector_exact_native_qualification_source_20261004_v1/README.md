# Exact native qualification runner — source only

Nothing has been imported numerically, loaded from a binary input, sent to the server or launched. The original acquisition metadata supports the two declared seed17 input sets on the corrected anogena-2 route; `INPUT_PROVENANCE.json` records the hash-bound chain. It binds no old warm state, native certificate or fitted outcome.

Callable loader: `runner.load_declared_inputs(graph_name, np, torch, device)`.
Future qualification callable: `runner.run_qualification(graph_name, output, device='cpu')`, where graph_name is `Squirrel` or `Photo`. It requires the authorized project process and sole UUID before data reads. Import and direct CLI invocation only expose source status. Unsupported provenance returns `UNRESOLVED_INPUT_PROVENANCE_REACQUISITION_REQUIRED`; runtime/operator/state failures return a saved unresolved/failure report.

The runner verifies and compiles sealed selector v3, uses its identical bound native adapter and unchanged warm functions, saves the newly generated warm checkpoint, checks native/K1/K4 identity, named Adam/state/RNG restoration, actual final-head affinity/AD, all five returned pretrial states and a disposable live-factor Adam map. It preserves selector nulls/failures and saves receipts/traces. It contains no predictive continuation call.

Actual NumPy/PyTorch/SciPy/PyG versions and PyG sparse/scatter operator behavior remain unresolved. Optional torch-scatter, torch-sparse and pyg-lib availability is recorded; required behavior must pass on the chosen actual device. The runner records total and phase wall/CPU/RSS costs and CUDA peaks when applicable. Selector trial costs are charged in aggregate, with per-map timers explicitly unavailable. Naturally missing non-common return coverage remains unresolved.

The existing recipes and 30-arm plan remain in `graph_curvature_selector_native_followup_source_outline_20261004_v2`; this package adds only the qualification implementation. Source syntax and metadata bindings have been checked with the standard library. Native correctness, memory, runtime, CUDA suitability and performance have not been tested.
