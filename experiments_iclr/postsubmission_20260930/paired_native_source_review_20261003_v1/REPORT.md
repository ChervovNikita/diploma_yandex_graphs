## Required correction: wrapped memory exhaustion

The sealed paired helper wraps geometry exceptions in `PairedGeometryError`, preserving their cause and original type in `.report`. Consequently, a genuine `MemoryError` wrapped during VJP/graph/JVP work becomes `qualification_failed` when its message lacks that CUDA phrase. The geometry receipt survives, but the status conflicts with the assay's promised resource deferral.

A stdlib mock using the actual sealed helper's extracted exception class reproduces this: wrapped `MemoryError('mock host memory exhaustion')` produces `qualification_failed`, whereas the same wrapped type with `CUDA out of memory` text produces `resource_deferred`. Both return exit code 1 and retain the geometry report. The fake exception was injected at the script's module-loading boundary to exercise its common top-level handler; no native branch, Torch, GPU, or numeric input was used. Classification should examine the exception cause/context chain and retained geometry error type. The new sealed version should test wrapped host and GPU OOM cases. This is a source receipt defect, not evidence against the method's quality.
