# Shared-message validation study source

## Purpose and current status

This package measures whether a common neighbourhood message can retain useful
ensemble predictions while reducing measured computation. The private root
and nonlinear member states remain. The detached arm removes the whole
neighbour-state gradient path, including self and cross-member paths; it does
not isolate cross-member gradients alone.

**Source only. No scientific launch or validation export is admitted.** The
author of this packet executed only standard-library source checks. No Torch,
dataset, labels, checkpoint, GPU, remote runtime, prior predictions or scores
were opened. This packet changes no older source or protocol.

## Compact evidence and primary results

Validation occurs every five completed updates and at the final epoch. Pooled
final-epoch accuracy/NLL versus the exact arm are primary. The lowest pooled
validation NLL checkpoint, with earliest exact tie, is secondary. At that
secondary checkpoint the member with lowest own validation NLL is selected,
with smallest-index tie. That same index is used for final gain diagnostics.
These gains reuse validation selection and are secondary/descriptive evidence.

Every training update has a scalar trace. Every validation record has pooled
and member CE sums, correct counts, pairwise disagreement and error overlap
counts. The package keeps:

- Initial parameters, fresh optimizer state and Torch CPU/CUDA RNG.
- Every improved secondary checkpoint, including optimizer moments and keys.
- A fixed final checkpoint.
- Selected and final member/pooled validation slices, never full-node logits.
- Separate selected and final forward replays, even if their epochs coincide.
- Trained final-state isolated inference timings.

At most 60 secondary improvements are possible. There are no per-update logit
copies. Sufficient-statistic replay verifies every scalar record and selection
rule; it is not an independent numerical forward replay of unimproved epochs.
Selected/final stored scores additionally receive numerical metric replay and
new full-graph forward replay under prospectively fixed tolerances.

The complete family report includes every task/arm/seed, each member accuracy,
NLL, pooling gains, pairwise disagreement/error overlap, actual full supervised
fit cost, trained latency and isolated training peak memory. It reports every
paired final seed difference and a two-sided 95% t interval with df=2. These
three-seed intervals describe optimizer variation on a fixed graph; they are
not significance, powered noninferiority or graph-population evidence. Nodes
are not independent replicate experiments.

The practical retention screen fails when mean accuracy loss exceeds 0.5 pp,
any seed loss exceeds 1 pp, or mean NLL increase exceeds 0.01. Mixed seed signs
are inconclusive unless a failure margin is exceeded. A passed margin screen
does not establish novelty, broad outperformance or acceptance.

The report exposes epochs 281–300 training losses and validation checkpoints
275, 280, 285, 290, 295 and 300. Continued exact-model learning limits conclusions
to the fixed budget. This source makes no convergence claim.

## Resource preflight and admission

`preflight.py` is separately gated engineering work. It requires a different
root request and cannot admit scientific fits or validation labels. For each
complete task/arm at seed 17 it measures one warmup and three train/backward/
AdamW updates, three validation-ID forwards/transfers, label-free CPU reduction
kernels, checkpoint/logit payload transfers and project-filesystem writes,
full byte hashes/readback, and five inference forwards. No quality values are
reported. Empty temporary files are unlinked before any weights/logits are
written; open descriptors close without retained state even on termination.
The I/O measurement is not an fsync/durability measurement.

The CPU proxy uses fixed-class log-softmax gathers and full pairwise reduction
work without validation targets. Root must explicitly qualify this engineering
proxy. `resource_forecast.py` uses all ten completed rows, worst observed costs
with a fixed 1.25 margin, maximum checkpoint improvements and four full hash
passes (creation, replay audit, family lock and separate family-lock audit). This margin is not a statistical confidence bound. Fixed validation
export, operator/preparation, source/audit/startup/manifest and prior completed
wall costs must be added. `artifact_plan.py` separately bounds all stored
state, selected/final fit and replay slices, transfers and work counts.

Scientific admission requires independent source/protocol audits, synthetic
forward/gradient/dropout/checkpoint checks, all-arm complete training memory
qualification, exact input/runtime/execution bindings, complete resource and
validation-export source gates, and a separately hashed root approval. The
whole forecast ceiling is 18,000 GPU allocation wall seconds; the cap is
21,600 seconds, peak reserved memory is at most 60 GiB and additional phase
disk is at most 200 GiB. Failed completed children and actual prior phase
bytes are conservatively charged. Successful bounded outer TERMINAL elapsed wall, including
bootstrap, CPU/IO, final hashes and supervisor teardown, is authoritative. GPU
busy time is not inferred. Inner child completion alone cannot qualify a run.

If the full 9,000-update family does not qualify, the package refuses to
shorten the budget, graph or matrix. The retained source is a reviewable plan,
not an experiment result. Additional controls, confirmation seeds, held-out
test evaluation and new independent manuscript review remain necessary before
strong scientific or novelty claims.
