## Training, stopping, selection, forwards and return

The bound canonical continuation was read directly, including its `train_update`, `evaluate`, warm acquisition and RNG helpers. The unchanged v3 caller was read for entry and start custody. All line references below refer to the verified v2 packet unless identified as canonical/v3.

- Training still sets train mode, zeros gradients, obtains one raw model forward, averages own-member TRAIN CE via flattened member/node logits, checks loss/gradients, performs coupled Adam, and checks parameters (adapter lines 368–388). Evaluation sets eval mode, obtains one raw forward, and uses the native pooled raw-logit mean for VALIDATION CE (391–400).
- Continuation epoch zero remains checkpoint eligible. Each update retains one training forward and one evaluation forward. The initial evaluation and selected replay add two evaluation forwards, so a successful continuation completing U updates has U training forwards, U+2 evaluation forwards, and 2U+2 raw-model invocations. This counts model invocations, not internal member or tensor operations. Midpoint saving adds a callback, not a forward (458–486, 551–563).
- Strict `value < best['validation_nll']` retains the earliest tie. Squirrel uses cap1950/patience250; Photo uses cap950/no patience. The midpoint remains Squirrel continuation950/native1000/actual1000 and Photo continuation450/global500/actual700. Training, evaluation, comparison, midpoint callback and stopping statements are AST-identical to canonical source.
- The hook runs after the final loop evaluation and patience decision and before `raw.load_state_dict(best['state'])` (487–551). It observes the last completed update and retains the existing native `value`; it cannot select a checkpoint or change any already completed update through this control flow.
- Squirrel terminal actual/native stage update is U+50. Photo terminal global-stage epoch is U+50 and actual update is U+250. Thus cap endpoints are Squirrel native/actual2000 and Photo global1000/actual1200. An earlier Squirrel stop is labelled native patience and is not fabricated as a full-cap endpoint. At U==cap the metadata reports cap reached, even if a patience inequality also happens to hold on that same last iteration; it is not a causal diagnostic of competing stop conditions.
- The observer return is ignored. On successful reporting the canonical selected restore, selected replay check (absolute NLL difference <=1e-6), `save_logits('selected', ...)`, `(best, metadata)` return, and existing callback arguments remain intact. Reporting errors propagate and prevent that return.
- Preserve the actual canonical state contract during qualification: the live model is restored to the selected model and put in eval mode. The live optimizer is **not** restored to selected history; it retains terminal Adam state and parameter references. Existing gradients also remain terminal gradients. `best['optimizer']` is the selected CPU snapshot. Demanding selected history in the live optimizer would test a new contract.

## Capture, metrics and RNG

`cpu_copy` detaches, transfers to CPU and clones (28–36). The hook clones the existing member logits and separately computes `logits.mean(0)` on the native device, then clones that result (511–524). The reporter receives those detached copies and scalar metadata; no model, optimizer or graph reference is passed. It checks CPU FP32 finite tensors, four members, compatible shapes and valid VAL node/class ranges (reporter 222–239). It does not independently establish the caller's graph/role freeze or compact-label pairing. Provenance descriptors are copied declarations; their hashes and actual role/label support need caller custody.

The source native NLL is the existing FP32/native-device scalar. Served/member metrics use CPU float64 log-softmax and probabilities from captured FP32 logits; Brier sums class squared errors and averages nodes (149–162, 240–278). Accuracy uses the native-device raw mean, whose finite values retain their ordering after float64 conversion. Independent metric qualification should compare the saved served tensor to the native mean witness, not silently replace it with a CPU or float64 re-average of member logits. CPU float64 NLL may differ from source FP32 NLL; neither reporting metric replaces selection or the frozen screen.

The initial wrapper RNG restore is the same helper/invocation as v3 `continue_one_arm` (reporter 334–339; v3 driver 159–168). Construction/loading precede that restore. The hook snapshots Python `random`, legacy NumPy global RNG, CPU Torch and all available CUDA default RNG states, then attempts restoration in `finally` (adapter 39–59, 510–550). Custom Torch/NumPy generators and unrelated backends are outside this unchanged inventory. A snapshot failure explicitly leaves restoration unavailable. A restoration failure propagates if no capture/observer error is pending; if one is pending, the secondary restoration error type is recorded and the original capture/observer exception remains pending. Source inspection does not prove that the actual states restore exactly.

## Failure receipts and preservation of exceptions

The following table describes ordinary caught Python exceptions, not durable guarantees during process death or unavailable storage.

| Failure region | Source coverage and retained evidence |
|---|---|
| Invalid/escaping paths, root creation failure, exclusive marker collision/failure before ownership | Exception propagates; no attempt-owned sidecar is promised. An existing marker is not overwritten. Caller accounting must retain these attempts. |
| Marker writing/closing after successful exclusive open | Ownership is set immediately after open; the outer catch attempts the run-level `_FAILED.json` sidecar. |
| Reporter constructor, bound source verification/loading, initial RNG restore | Outer catch attempts a run-level sidecar before any terminal directory exists. Stage, exception and unknown endpoint fields are retained; bindings have availability and verification status. |
| Native continuation failure before the hook | Outer sidecar covers the failed invocation. Endpoint is not captured; update/stop/selected values are explicitly unknown. The sidecar is not a substitute for native trace accounting of the last completed update. |
| Hook metadata/snapshot/member-copy/native-mean-copy failure | Scalar endpoint context is populated before snapshot/capture. Completed or partial capture timing is retained where available. Restoration is attempted only after a complete snapshot. The outer sidecar covers the error. |
| Terminal metadata, directory creation, validation, metrics, tensor write/hash read, binding read, report construction/final JSON write | Reporter stages are guarded. A failure in this attempt-created terminal directory attempts `REPORT_FAILED.json`; all cases after marker ownership also attempt the outer sidecar. Directory collision produces an outer receipt and does not write into prior evidence. |
| RNG restoration failure after the observer | Outer sidecar includes restoration status/type and available timing. Original capture/observer error is preserved if already pending. |
| Selected state load/replay check/selected callback failure after reporting | Outer sidecar covers the failure and retains `reporter_completed`/endpoint context. The wrapper stage is broadly `native_continuation`; the exact failing tail operation is not separately tagged. |
| Failure inventory/identity/bindings/exception-string/receipt construction or write failure | Entire receipt construction/write is protected. Inventory has an unavailable fallback. Secondary receipt errors are suppressed and the original exception is re-raised. Storage can prevent any durable receipt. |

The source changes address v1 F1 (coverage starts before constructor/loading, and directory creation is guarded), F2 (endpoint, capture cost, bindings and unknown-field inventory retained), and F3 (complete best-effort receipt construction protected) (reporter 77–140, 209–295, 298–354). The outer receipt adds hook restoration context after inner reporter unwinding. An inner observer receipt cannot contain later RNG restoration evidence and marks source verification false by default; the outer receipt supplies the actual loader verification flag. Available selected IDs and terminal source NLL are recorded, not a selected model/Adam snapshot or full selected-NLL record. A terminal success JSON establishes that reporting completed at a pre-restore endpoint, not that the wrapper later returned successfully. The STARTED marker stays STARTED; caller selected artifacts/return/run accounting establish final completion.

All failure receipts are single-use/exclusive. No retry, new endpoint or overwrite is authorized. Under the stated stable-path assumption, root/output containment checks keep supplied writes within the project phase. Mutable symlink/concurrent parent replacement, externally mutated modules/objects, arbitrary custom observers and unrecoverable allocation/storage/process failures are not audited guarantees. Those are coverage limits; no source blocker is inferred merely from their absence.

## What must be measured for observational qualification

AST equality rules out an ordinary source change to the pre-hook loop, but does not supply numerical equivalence. Exact-runtime tests should bind executed-source custody, interpreter/dependency versions, backend/device and the authorized VAL support, then measure the following boundaries on isolated disposable native copies.

1. **At continuation entry:** compare the initialized live model/buffers/spec/stage, alias relationships, all submodule modes, gradient contents/presence, named Adam states/steps/groups/options/parameter links, graph and TRAIN/VAL tensor identities/values, and default RNG states against the original caller path. This resolves constructor/loading/validation-copy effects and verifies that initial RNG restoration starts the same training state. Do not infer this from stored source tags alone.
2. **Immediately before the hook:** independently witness existing member logits, the native raw-logit mean and existing source NLL; terminal live model/buffers/modes/gradients, optimizer/alias state, graph/label support, default RNG state; completed updates, cap/patience and stop flags; the selected `best` state/optimizer/NLL/IDs and midpoint/callback/trace history. These values are already determined by native training.
3. **After capture/reporter/restore:** compare the live model/buffers/modes/gradients, optimizer states/groups/links, inputs, selected `best`, and witnessed native logits to the same pre-hook values; compare Python/NumPy/CPU Torch/all admitted CUDA default RNG states exactly. Verify that CPU saved payloads are detached independent storage, FP32 member copies equal the witness, served copy equals the native mean, and VAL nodes/labels/provenance match the authorized pack. Verify independent served/member accuracy, NLL and class-summed Brier, with the declared precision difference. An intentional payload mutation and RNG draw in a disposable observer can test copy isolation and restoration without claiming that it is the supplied observer.
4. **Across the selected tail:** from the same terminal/best/RNG boundary, compare observer-disabled and enabled paths through selected restore/replay and callback. Compare selected logits/replay NLL, complete `best` and returned metadata, callback order/names/arguments, final live selected model/eval modes, terminal live optimizer/gradients, and post-return default RNG states. Count raw-model invocations: hook delta0; selected tail delta1 in both paths. Outputs should be compared as values/state, not Python object identities across independent clones or serialized checkpoint file-byte identity.
5. **On failure paths:** inject the listed stage failures on disposable copies and verify same original exception object/type/message is propagated where promised; a simultaneous observer+restore failure preserves the observer exception; snapshot failure does not claim restoration; receipt/inventory failure does not mask the primary error; directory/marker collision does not overwrite; and no post-failure successful return is asserted. Exercise representative pre-hook native and post-hook tail failures through the actual wrapper. Missing endpoints must stay unknown. Test unavailable storage separately as an expected accounting limit, not as proof that a receipt exists.

These measurements can use the actual hook and selected tail with independently isolated state at the boundary, with read-only witness instrumentation and exact bound code custody. They must not use a mock model alone as evidence about actual native tensors/backends. Both prescribed backbones and naturally available cap/patience paths should be represented; missing coverage must be stated. Focused runtime/exception fixtures establish the behavior exercised by those fixtures and never stand in for a measured frozen full native trajectory.

## Which risks require a complete native repeat

Qualifying this after-training hook does **not**, by itself, require duplicate full training for every arm/seed or all thirty continuations. A native run that reaches the actual boundary can supply an in-memory terminal/best witness; isolated copies allow paired hook/tail checks without repeating the already completed updates. Constructor/loading/entry checks, tensor/metric checks, RNG restoration checks, callback/return checks and injected failures can be tested without repeating the whole schedule. A full completed native run may still be needed to obtain representative terminal states that do not yet exist; that is acquisition of coverage, not a mandatory duplicate run for each failure fixture.

Repeating complete native training is justified if (a) the intended claim is empirical numerical identity of the entire frozen trajectory and return from identical starts, (b) entry-state/RNG differences, training-affecting side effects, nondeterminism or measured divergences remain unresolved, or (c) cumulative full-schedule resource/success/stop coverage must actually be established and no adequate measured run exists. A localized test cannot prove a full-trajectory empirical claim or that all thirty prescribed arms fit and finish. Existing pending fresh warm/transport/selector/trial/actual-native qualification and the later prescribed development schedule remain separate requirements in the bound outline; this reporting review does not qualify or alter them.

Because the successful hook executes after every update, a post-hook RNG mismatch cannot retroactively alter its completed training trace. It can change later replay/callback/future work, so resolve it at the boundary and tail first. Capture/IO allocation failure can prevent successful post-training completion and must be charged/retained; it does not establish that earlier numerical updates changed. No new outcome-driven early stop, shortened predictive pilot, alternative endpoint, retry or replacement arm is introduced by this qualification recommendation.

## Endpoint and cost coverage limits

- Successful capture wall/process CPU starts immediately before endpoint metadata and includes metadata, canonical RNG snapshot, member CPU copy and native mean/CPU copy up to dispatch (adapter 491–519). Partial failures update that boundary in `finally` (530–534). No model forward is added.
- Observer body wall/process CPU begins before endpoint parsing/directory creation and includes validation, CPU metrics, tensor serialization, serialized-file read/hash, tensor digests and report construction. Its successful stored boundary excludes final report JSON writing and subsequent RNG restoration (reporter 213–278).
- Observer-failure elapsed time includes attempted final JSON writing and precedes inner receipt construction. The outer failure interval begins before wrapper path/marker work and includes constructor/loading/initial RNG restore, native continuation, hook/reporting and failure unwinding, including any inner receipt work, up to outer receipt construction. Restoration elapsed is available in the outer failure context. These nested/overlapping intervals must not be summed as training cost.
- Successful restoration status/timing occurs after successful terminal JSON construction and is not persisted by the successful wrapper. There is no successful total-wrapper or full-schedule timing, no successful final-JSON timing, and no full failure-receipt construction/write timing. Additional independent accounting is needed if those totals are required.
- `perf_counter`/`process_time` record the stated host intervals. Native-device reduction/CPU transfer can synchronize pending device work; there is no explicit general CUDA synchronized component timer or GPU-time accounting. Host process CPU is not GPU execution time. No host RSS, CUDA allocated/reserved peak, storage peak, full-schedule feasibility, cold/warm serving cost or selected-endpoint/member metric artifact is supplied by this terminal-only packet.

The endpoint/capture fields therefore support limited terminal observation and partial accounting. They supply no heldout evidence and no claim of predictive improvement, full-run equivalence or resource feasibility. This source review is complete; exact-runtime qualification remains unperformed.
