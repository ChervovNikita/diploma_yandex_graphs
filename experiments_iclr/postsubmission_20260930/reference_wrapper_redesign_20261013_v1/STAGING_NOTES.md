# Allocation staging notes

Four preparation-only transfer attempts failed before a completed receipt.
The first could not overwrite the read-only old public launcher. The uploader
now writes an exact temporary file in the same project directory and atomically
replaces that specifically retired entry point, preserving its original bytes
in the declared historical copy. No frozen controller or plan is changed.

The second saw Git index-refresh progress before its READY handshake. Git status
now suppresses incidental progress on that handshake and disables optional
index locking. No scientific jobs were created by either attempt. Previously
uploaded design files remain the same disabled preparation packet.

The third completed transfer but could not verify an OGB author entrypoint at
its historical phase path. The redesign now binds fresh byte-identical saved
author-source snapshots inside its own native_sources directory. Original
historical paths are retained in the manifest and are not overwritten. No
scientific job was created; source qualification remains a separate requirement.

The fourth binary transfer triggered an SSH escape sequence inside the raw
packet before extraction. The packet uploader now disables SSH escapes with
`-e none`. It still uses the required verified allocation route and remote TTY.
No scientific process or GO was created.

The initial publication attempts stopped at Git's whitespace check on frozen CSV
rows and then two extra final blank lines. No commit or push occurred. The publication helper now recognizes valid
CRLF and checks authored changes while leaving literal author/reference captures
unchanged. Its first version is preserved under history. The same reviewed
staging can be resumed; it does not start scientific execution.
The two authored files were trimmed at EOF and their static/freeze receipts
updated; no numerical or methodological definition changed.
