CPU process RSS is cumulative and includes preprocessing; it is not attributed to one CUDA stage.

Original batch custody hashing is real work: its GPU tensors copy to CPU for byte hashes, and validation allocates selected row clones. Calls during transfer, q construction, streaming forward, custom backward and final custody are all included (five per recipe). Diagnostic finite checks and per-private tensor summaries are included in their stages. Diagnostics report force presence/finite status and sizes/ranges; zero force is accepted. No accuracy, validation metric or competence threshold is calculated.

Own tensor references are released and the current process's CUDA caching allocator is cleared between cases. Other jobs/devices/processes remain untouched. Device free memory can change because other processes share the device; observed free memory and own allocator peaks are recorded separately. There is one attempt per recipe, no warm-up/trial sequence. Any mismatch, OOM, deterministic-kernel error, nonfinite value or custody failure stops the family with stage/failure metadata, exit1 and no retry/device/precision/batch fallback.
