## Normalization and likelihood

The frozen conditional law is `p(z|C) proportional to exp(eta dot z + g_C(K_L,K_R))` (`FROZEN_SPEC.json:61`, `README.md:44-47`). For one side define `A_j(k)` as the sum of `exp(sum eta_i z_i)` over its first `j` slots having `k` included bits. Then `A_j(k)=A_{j-1}(k)+exp(eta_j) A_{j-1}(k-1)`, with the single feasible initial coefficient `A_0(0)=1`.

`log_coefficients` implements this recurrence using only reachable cells (`count_density.py:19-23`): degree zero is preserved, each interior cell is logaddexp of exclusion/inclusion, and the new highest count has only its inclusion branch. It never differentiates a logaddexp of two unreachable negative infinities. `log_normalizer` includes every pair `0<=k<=n_L`, `0<=l<=n_R` and adds its unrestricted supplied table entry before logsumexp (`:75-80`). Hence it computes the stated partition function in real arithmetic without count truncation, sampling, or replacing the joint potential by separate side terms.

For nonempty support, `query_nll` subtracts the observed unary sum and the single observed count-pair potential, then divides by the entire query support size (`:83-94`). There is no missing Bernoulli normalization factor: this law is written with unnormalized unary weights `exp(eta_i z_i)`. When `g=0`, the resulting partition function factorizes into `product_i(1+exp(eta_i))`, giving independent sigmoid marginals. A scalar shift to all potential entries adds the same scalar to logZ and the observed potential and cancels from NLL and probabilities.

`CountSingle.source_nll` returns exactly one loss per query, including an empty support zero (`count_model.py:138-153`). To check the specified outer reduction I additionally read `learning.py:1-150`: the positive and negative query-group means are taken separately, include every empty-query zero, and are added with coefficient one (`learning.py:43-60`). This matches `README.md:69-74`. No nonempty-query renormalization or global slot-weighted reduction appears there.

## Exact unary marginals with context held fixed

`unary_marginals` explicitly runs without autograd and detaches both unary arrays and the potential (`count_density.py:97-100`). Its complete count-pair probability is softmax of the same ESP/count-potential state scores (`:104-109`). Thus the count-law seed is the conditional count distribution for the fixed potential, not a total neural-context derivative.

For a side prefix ending at slot `j`, the conditional inclusion probability on an interior count `k` is `exp(eta_j) A_{j-1}(k-1) / A_j(k)`. The code computes it as sigmoid of the inclusion versus exclusion log weight (`:58-60`). Count zero must exclude, and count `j` must include; both boundaries are propagated explicitly (`:54-56`). Interior inclusion mass moves from count `k` to predecessor `k-1`, while exclusion mass moves to predecessor `k` (`:61-65`). Consequently the seeded reverse pass marginalizes all suffix slots and returns every slot's inclusion probability. The per-slot division by total mass at `:66-68` is identical to the unit-mass reverse in exact arithmetic; it is not epsilon clipping or a count approximation. Its numerical effect remains for fabricated QA to measure.

The side marginal/count-sum assertions at `:110-114` are necessary consistency checks, but alone would not establish all unary marginals. The independent pattern oracle supplies the stronger comparison. At the neural readout the original/swapped contexts, eta and potential are detached (`count_model.py:123-128`), and completed residual weights are detached again (`:130-132`). Native common features remain live and weight one; residual features receive `1.05*mu`. The resulting target is one native nonlinear decode of expected completion (`:129-133`), matching `D(E[Z])`, rather than an expected nonlinear decoder output.

## First-order gradients

For independent density inputs with fixed `g`, `d logZ / d eta_i = mu_i` and `d logZ / d g(k,l)=p(K_L=k,K_R=l)`. Therefore the nonempty query loss gradients are `(mu_i-z_i)/r` and `(p(k,l)-1[(k,l)=(K_L(z),K_R(z))])/r` for `r=n_L+n_R`. The differentiable reachable-cell recursion and observed numerator at `count_density.py:15-23,75-94` implement these identities.

The model's auxiliary branch builds a fresh differentiable potential from live contexts (`count_model.py:146-152`). Differentiating source NLL therefore includes the intended chain-rule gradients through learned context and its eta dependence; the completion readout does not. The total derivative of a neural `g(eta)` is not itself a unary marginal. The explicit witness at `fabricated_qualification.py:93-98` demonstrates that distinction, and the separate marginal API holds the potential fixed.

`fabricated_qualification.py:51-59` checks independent-unary and potential derivatives of logZ against enumerated unary/count probabilities for every support geometry. `:60-69` checks NLL derivatives for one chosen observation pattern per nonempty geometry; NLL values are checked for every pattern. `:99-105` is a first-order FP64 gradcheck over both unary sides and every potential input in one 2+1 geometry. These are meaningful prepared checks, not performed checks. The empty NLL's zero parameter gradients, neural head/context gradients, checkpoint recomputation and main-only detachment probes are not established by this routine and remain in the model gate.

The enumeration's explicit `(2**size,size)` reshape handles the empty state as shape `(1,0)` (`fabricated_qualification.py:13-14`).
- Singleton support has only exclusion and inclusion boundary branches. The reverse returns the singleton count-one probability directly. Both possible one-sided singleton geometries and both observation labels are included by `:29-47`.
- All one-sided supports through size eight are included by the complete partition loop. No empty-side maximum or normalization divide-by-zero appears in the density. Neural hypothetical count fractions use `max(n,1)` and context pool means use a clamped divisor with an empty zero sum (`count_model.py:45-50,85-102`).
- The prepared extreme fixtures include mixed `[-1000,1000,25,-25]`, all `1000` and all `-1000` unaries with a full nonuniform 3x3 potential (`fabricated_qualification.py:85-92`). The density source has no explicit clipping, epsilon, sampling or truncation fallback. These extreme checks compare logZ and marginals only, not extreme NLL gradients.
- Exactness here is an algebraic inference property. FP64 still rounds and can underflow tiny probabilities; arbitrary finite machine inputs can overflow intermediate coefficient/state sums. Inspection cannot turn the three bounded fixtures into a universal numerical guarantee for every finite value or every uncapped native support size.

## Endpoint exchange and enumerator independence

For deterministic corresponding native inputs, exchanging endpoints exchanges left/right slots and their counterpart identities. The endpoint sum/product and common sum/mean are invariant. Flipping the two role coordinates maps the original slot map to the swapped slot map; swapping the side pools and left/right size scalars then interchanges the two contexts (`count_model.py:74-103`). The shared head gives `g_C(k,l) = [H(C,f(k,l))+H(Cswap,f(l,k))]/2`; exchanging contexts/sizes/counts yields the transposed potential (`:41-56`). Exact density-array exchange therefore swaps the unary output halves. Full native scorer/order and floating accumulation parity still need the prescribed fabricated model tests.

The oracle constructs every bit vector, computes its two count coordinates, evaluates the stated law's unary sum plus direct `g` lookup, and normalizes those enumerated weights (`fabricated_qualification.py:11-19`). It does not call the ESP recursion, prefix table, reverse pass, normalizer or marginal API to derive expected values. It shares generic Torch floating operations and the assertion helper, so it is an independent combinatorial implementation rather than an independent numerical backend. The expected count distribution is explicitly accumulated from pattern probabilities (`:41-44`).

By source arithmetic, the main loop prepares 45 support geometries, `sum_{r=0}^8 (r+1)*2^r = 4097` observation patterns, and 44 nonempty NLL-gradient geometries. The one positive-correlation witness, three extreme fixtures, context derivative witness and gradcheck are additional checks not included in those return counters.
