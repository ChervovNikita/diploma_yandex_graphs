## Temporal graph and fitted features

The export cuts timestamped DB tables inclusively at 2010-01-01, performs the native dangling-FK correction, and does not reindex (`custodian_export.py:25–28`). The saved `Table.upto` and `Database.upto` implement the inclusive cutoff. Native reindexing sorts timestamped tables before assigning IDs; therefore removing a chronological suffix preserves the stable prefix IDs. Public reading rejects nonconsecutive IDs, timestamps after cutoff and invalid surviving FKs. Whether the admitted files are genuinely the native sorted/reindexed files remains a custody qualification.

`chronological_graph` derives stypes from `db.upto(2005-01-01)`, removes PK/FK input features, fits a single Frame Dataset per table on that cutoff, and transforms the complete public table with its frozen converter (`features.py:38–60`). The pinned Frame implementation computes column statistics in `materialize`, constructs categorical mappers from those fitted counts, excludes any designated target from predictor columns, and exposes the fitted callable through `convert_to_tensor_frame` (`sources/frame023_dataset.py:184–323, 553–665, 748–751`). No independent full-table fit is performed. The constant-feature fallback matches the native graph builder's intent. Untimestamped drivers/circuits/constructors remain fully available as an explicitly declared benchmark assumption.

The loader uses native table input, supplied per-forecast seed times, directional disjoint temporal sampling, uniform strategy, zero workers and the fixed fanouts (`run_stage1.py:51–64`). The pinned PyG sampler passes `node_time` and supplied `seed_time` into `pyg.hetero_neighbor_sample`, and temporal sampling forces disjoint mode (`sources/pyg261_neighbor_sampler.py:104–142, 305–314, 351–445, 525–545`). It performs CSC/time ordering internally because `is_sorted=False`; the independent row-wise edge sorting does not incorrectly assert temporal CSC ordering.

Batch QA checks original forecast root IDs/times, separate root component IDs, target attachment, and sampled timestamps against each node's component seed time. A two-root repeated-driver probe checks that different forecast dates survive (`run_stage1.py:67–123`). The compiled sampler's actual behavior, missing-time metadata handling, and model compatibility on sampled TensorFrames remain runtime qualifications. A useful additional QA assertion would check that every sampled edge joins nodes with equal component IDs; the current QA verifies distinct root components and per-node times but does not independently inspect cross-component edges. This is a coverage improvement, not evidence that the pinned disjoint sampler produces incorrect edges.

As a result, this remains a benchmark-cohort qualification and cannot support a production cohort claim. No forecast cohort extension or new task generation is included.
