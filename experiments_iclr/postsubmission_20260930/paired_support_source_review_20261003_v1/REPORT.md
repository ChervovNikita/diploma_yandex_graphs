## Evidence limits and nonblocking concerns

1. **Fixture coverage (C1).** The substantive reference is independent where it matters: analytic Jacobian, factored dense Bernstein bank, and a single matrix projection replace subject AD, polynomial expansion, and repeated projection code. However, all Torch fixtures use FP64, identity `target_nodes`, and a node-local Jacobian. They do not numerically qualify native FP32 arithmetic or a reordered, cross-node closure. This review's rational mapping check is algebraic evidence only. The packet already requires native actual-closure AD qualification, so this is an evidence limit rather than a source blocker.
2. **Sparse-product error accounting (C2).** `graph_sparse_products += 3` happens before each bank primitive. If that primitive aborts, the receipt is a scheduled charge; it cannot establish three completed sparse products or the actual partial count. `COSTS_AND_LIMITS.md` discloses this. A future consumer should preserve that interpretation explicitly, ideally with separate scheduled/completed fields, and use measured timing/memory for native resource accounting. Acceptance is unaffected.
