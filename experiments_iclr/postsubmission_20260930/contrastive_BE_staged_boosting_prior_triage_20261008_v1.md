# Staged shared-backbone boosting: no new rule promoted

8 October 2026. The saved staged-residual design and its closest-prior review already resolve the main operational alternatives. No new primary retrieval or method read is needed. This is a triage conclusion, not an empirical finding that sequential training cannot help.

## What the closed errors motivate

Wiki24 identifies competent but redundant unit-plus-contrast members and strict common wrong rivals. A new route must learn sufficiently different correct evidence; those unchanged probabilities cannot be fixed by a convex pool alone. Direct12 gives no positive head-refit result. Neither observation diagnoses a shared-weight overwrite problem or proves that a residual weak learner can repair the errors.

## Three complete operational cases

| Rule | Earlier route functions | Relation to existing work |
| --- | --- | --- |
| Joint or cyclic private updates on own CE plus actual pool risk, while shared weights keep own CE | Changing the common weights also changes earlier routes, even if their private factors are fixed. | With matched pool, reductions and block permissions, this reuses the current internal-credit/GNCL policy. Updating one private block at a time changes the schedule; it does not create a residual-learning principle. Mol18 and WikiCS use different task losses/pools, so their numeric objectives are not asserted identical. |
| Freeze the common model and old private rows, then fit each new internal-BE row sequentially on own and pool risk | Deterministic earlier functions can remain fixed in the present stateless architecture. New early/intermediate factors can recompute that route's nonlinear graph states; this is not inherently a final-head refit. | The pool term is still ordinary collective-risk optimization, now in a restricted stagewise coordinate schedule. This differs from the live Mol18-I policy, but frozen shared features, sequential neural residual learning and staged private ensembles already have direct prior. No new rule is established by substituting internal factors for the weak-learner family. No frozen failed bank is proposed. |
| Fit genuine additive/Newton residual learners, followed by fully corrective refinement | Earlier functions are deliberately revised during the corrective pass. | GrowNet already defines this mechanism. A graph/BE weak-learner restriction could be an attributed adaptation, not a newly discovered boosting algorithm. No such adaptation is proposed here. |

For the actual probability mean, the active member's pooled-CE logit gradient is

    [p_m(y) / sum_j p_j(y)] * [p_m - one_hot(y)].

Calling that gradient an ensemble “residual” does not change the supervised objective. A pooled Brier term similarly supplies the ordinary softmax-Jacobian pullback of the probability residual. Own-risk anchoring plus either pool loss remains known individual/collective-risk composition; all loss reductions, parameter recipients and optimizer state must be specified before claiming an update equivalence.

## Changing shared weights is the central limitation

For an older route, a shared displacement changes its logits through its shared Jacobian even when its private parameters do not move. Frozen private rows are therefore not frozen predictors. A residual target computed from an earlier predictor can become stale during common-weight learning; recomputing it each step instead defines a coupled training procedure whose complete objective/update must be stated.

This does **not** mean all boosting must preserve earlier functions forever. Fully corrective boosting intentionally revisits them. It means classical stagewise or weak-learner guarantees cannot be transferred merely because a shared model is trained in phases. An exact preservation constraint, distinct private subspaces, or another shared-update rule would change the method and require separate evidence; none is introduced here.

## Decisive saved primary scopes

- **GrowNet**, [arXiv:2002.07971v2](https://arxiv.org/html/2002.07971v2), saved §§3/3.1/3.2, Eqs1–3 and Appendix B/Algorithm1: new neural learners fit the second-order target −g/h with h weighting and previous hidden-feature access; the fully corrective pass updates preceding learners and boosting rates. Native multiclass graph reproduction was not qualified.
- **BoostResNet**, [arXiv:1706.04964v2](https://arxiv.org/html/1706.04964v2), saved §§2–4.3 and Algorithms1/2: sequential residual representation blocks use temporary classifiers and telescope into one final network. This prevents an ensemble-necessity claim from residual staging alone; its proof assumptions were not certified for these graphs.
- **AdaGCN**, [arXiv:1908.05081](https://arxiv.org/abs/1908.05081), saved method/Algorithm1 conclusion: sequential hop classifiers, warm transfer, TRAIN-error reweighting and centered-log-probability combination already establish graph boosting ancestry. **BGNN**, [arXiv:2101.08543v1](https://arxiv.org/html/2101.08543v1), saved §3/Algorithm1, already fits additive trees to graph-dependent GNN feature updates.

The existing staged-private-graph proposal already defines fixed peers, a competent frozen base, raw-feature graph correction paths, own CE plus pool Brier, and matched staged/interleaved/own-only controls. Its closest-prior review covers Deep Sub-Ensembles, TreeNets and Hydra as well as the sources above. It is not reopened or renamed as internal-BE novelty. Recent unread AdaGNN and other inaccessible bodies remain unresolved; their absence supplies no originality evidence.
