# Finite resource and startup coverage

This package prepares metadata and startup checks. It does not launch scientific jobs, connect to 18.77, change host settings or authorize a GO.

## Source geometry

`source_geometry.py` reads the actual native PolyFormer `hidden`, `d_ffn`, `n_head`, `nlayer`, `K` and `multi`, and retains nested encoder/predictor/decoder declarations. Missing fields remain unknown. The previous generic catalogue's width/depth/head defaults did not describe the native models. Its 122 nested-native representatives are disclosed in the supplement, but correcting a representative does not prove that it is the maximum geometry of the final plan.

`catalogue_final_geometries.py` can run once against the immutable final master on the allocation. It groups declared shapes by actual source factory and branch, includes every fit's geometry and budget, preserves paid-parent scope and GPU assignment, and rejects original-paper datasets. It makes no timing, dominance, complete state or physical admission claim. A proved source-family maximum geometry/full-state envelope can cover lower configurations; separate resource callbacks for every fit are unnecessary. Source dependency and geometry equality must be established before reuse.

## One command per host after synchronization

The normal final launcher can call `preflight_host_budget.py` internally before starting its worker slots. The preflight verifies the final master, physical host/GPU binding, reviewed source runtime admission, current project filesystem space, whole-host available RAM, and each GPU's present free VRAM. Missing full-state/destination bounds return PENDING. Insufficient resources return REFUSED. Every outcome is saved at a fresh project path. No worker is started by this helper and it creates no scientific GO.

Two workers per GPU means at most two concurrent fits. A reservation broker must delay a second fit unless their combined live reservations fit the present GPU budget and whole-host RAM/disk envelope. Two65,536MiBPolyFormer fits cannot share an approximately80GBGPU. On 18.77 the RAM/atomic-write/paid-ancestor envelope includes all four potentially live slots across its two GPUs, not each GPU in isolation. Fits, retries and selected-model serving reconstruct on the same assigned device; cross-runtime/device learned-state reuse is not admitted.

The final disk bound must include data and feature caches, complete adapter/native L state, full selected HPO cohorts, compact serving states where explicitly audited, all transitive paid ancestors and retries, integer tapes, banks, cost/trace/failure history and concurrent atomic recovery writes. Retention cannot be credited until the actual controller policy allows it. Total written bytes and peak retained bytes differ. Existing files consume the observed free filesystem budget; quota admission remains explicitly scoped by the root's destination review.

The current manifest template is intentionally incomplete and disabled. 18.77's source runtime, disk, quota, RAM and both GPU UUIDs must be checked after the user reauthorizes that route and code/data synchronization completes. The complete source/run plan and physical destination admission are separate deliverables. Use normal host execution and ordinary caches; no filesystem namespaces, mounts, sudo or host setting changes are introduced.
