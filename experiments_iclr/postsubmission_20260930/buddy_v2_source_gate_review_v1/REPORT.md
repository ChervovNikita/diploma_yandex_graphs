**Architecture and native identity.** `models.py:22` extracts the complete saved BUDDY class by AST and executes that class with its native Torch/F/Linear globals. Native width 1024, width 256 and matched width 266 all use this class.

The native branch projects each endpoint with `lin_feat`, forms the within-pair Hadamard product, then applies `lin_out`, feature BatchNorm/ReLU/dropout. Its structural branch concatenates raw counts and counts divided by the square root of the two weighted degrees, replaces nonfinite quotients with zero, and applies the native structural linear/BatchNorm/ReLU/dropout sequence. The final concatenation preserves the native feature cast to `torch.float`, including in the float64 parity path (`models.py:107` and vendor BUDDY `forward`:343).

`FactorizedBUDDY` preserves those operations, with every one of the four native linear maps represented as `((x*r) W^T)*s+b`. Shared W and bias and private R/S match the declared port. Endpoint products are formed inside each member. All BatchNorm modules, including the registered unused bn_RA, have separate member affine parameters and buffers; the member axis is never merged into the BN sample axis. Training initialization uses seeded random-sign R and all-one S. The identity tests use all-one R/S intentionally. `IndependentBUDDY` constructs four distinct native models under member seeds `seed+10000*m` and receives four Adam optimizers. Its loss is own-member BCE; factorized loss is mean member BCE; deployment and selection use mean raw logits. The resulting gradient scaling and different dropout layouts are correctly disclosed rather than claimed as identical optimizer trajectories.

Independent parameter arithmetic gives native `h*h+133*h+323`: 272 structural-linear parameters, 32 structural-BN parameters, 2 unused RA-BN parameters, and the feature/final layers and BN. The resulting counts are 1,185,091 native1024; 99,907 single256; 106,349 factorized4; 399,628 independent4; and 106,457 matched_single. **Genuine blocker B1 — hashing module registration.** `cache_builder.py:89-93` creates `pinned_buddy_hashing` using `module_from_spec` and `exec_module`, but does not register the created module in `sys.modules` before executing/constructing the native PyG MessagePassing classes. The supplied PyG 2.7 traceback reaches Inspector `_globals`, whose `sys.modules[module].__dict__` lookup raises `KeyError: pinned_buddy_hashing` during `MinhashPropagation()` construction. Thus the native hasher cannot be instantiated in the declared qualification runtime, and both the sketch test and real cache construction are blocked. This is a concrete implementation defect, not a preferred architecture change. Repair the dynamic import glue in a new source version by installing the module under its exact spec name before execution, preserving the native vendor bytes and the seven tests; requalify that sealed source. A stdlib mock of the exact glue reproduces the missing-registry lookup. This audit does not modify v2 or certify any proposed v3 repair.
