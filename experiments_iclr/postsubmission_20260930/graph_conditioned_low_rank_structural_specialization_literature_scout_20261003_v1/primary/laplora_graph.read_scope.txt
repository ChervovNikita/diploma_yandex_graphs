BLOCK 18 [S2.SS1.p1.1] II-A Spectral View of Oversmoothing
We begin from a spectral characterization of oversmoothing. Let L denote the normalized graph Laplacian with eigendecomposition

BLOCK 19 [S2.Ex1] II-A Spectral View of Oversmoothing
L=U\Lambda U^{\top},

BLOCK 20 [S2.SS1.p1.2] II-A Spectral View of Oversmoothing
where \Lambda=\mathrm{diag}(\lambda_{1},\dots,\lambda_{N}) . A standard GCN layer applies the propagation operator

BLOCK 21 [S2.Ex2] II-A Spectral View of Oversmoothing
S=I-L=U(I-\Lambda)U^{\top},

BLOCK 22 [S2.SS1.p1.3] II-A Spectral View of Oversmoothing
corresponding to the spectral filter g_{\text{GCN}}(\lambda)=1-\lambda .

BLOCK 23 [S2.SS1.p2.1] II-A Spectral View of Oversmoothing
After t layers, the component of a node representation along eigenvector u_{i} is scaled by

BLOCK 24 [S2.Ex3] II-A Spectral View of Oversmoothing
(1-\lambda_{i})^{t}.

BLOCK 25 [S2.SS1.p2.2] II-A Spectral View of Oversmoothing
Since |1-\lambda_{i}|<1 for all nonzero Laplacian eigenvalues, all non-constant spectral components decay exponentially. As depth increases, representations collapse into the low-frequency eigenspace, resulting in oversmoothing.

II-B Weakening Contraction Without Instability

BLOCK 27 [S2.SS2.p1.1] II-B Weakening Contraction Without Instability
Delaying oversmoothing requires weakening this per-layer spectral contraction. Consider a modified filter

BLOCK 28 [S2.Ex4] II-B Weakening Contraction Without Instability
g(\lambda)=(1-\lambda)+\Delta(\lambda).

BLOCK 29 [S2.SS2.p1.2] II-B Weakening Contraction Without Instability
To slow contraction while preserving stability, the modified filter must satisfy

BLOCK 30 [S2.Ex5] II-B Weakening Contraction Without Instability
|1-\lambda|<|g(\lambda)|<1\quad\text{for all }\lambda\in(0,2].

BLOCK 31 [S2.SS2.p2.1] II-B Weakening Contraction Without Instability
These constraints strongly restrict admissible corrections. In particular, additive corrections that are not aligned with (1-\lambda) either fail to uniformly weaken contraction or lead to instability near \lambda\approx 0 . Consequently, the only safe way to reduce contraction across the spectrum is through multiplicative scaling of the base Laplacian filter.

BLOCK 32 [S2.SS2.p3.1] II-B Weakening Contraction Without Instability
We therefore restrict attention to filters of the form

BLOCK 33 [S2.Ex6] II-B Weakening Contraction Without Instability
g(\lambda)=(1-\lambda)\bigl(1+\beta(\lambda)\bigr),\quad\beta(\lambda)\geq 0,

BLOCK 34 [S2.SS2.p3.2] II-B Weakening Contraction Without Instability
which strictly weaken contraction while remaining stable as long as

BLOCK 35 [S2.Ex7] II-B Weakening Contraction Without Instability
|(1-\lambda)(1+\beta(\lambda))|<1.

II-C Laplacian-LoRA Operator

BLOCK 37 [S2.SS3.p1.1] II-C Laplacian-LoRA Operator
Laplacian-LoRA instantiates this admissible class through a spectrally anchored, low-rank residual adaptation. Inspired by LoRA in large language models which adapts a frozen linear operator via a low-rank residual, we adapt the graph propagation operator directly in the Laplacian eigenspace.

BLOCK 38 [S2.SS3.p2.1] II-C Laplacian-LoRA Operator
Specifically, Laplacian-LoRA introduces a residual spectral branch with filter

BLOCK 39 [S2.Ex8] II-C Laplacian-LoRA Operator
g_{\text{LoRA}}(\lambda;\alpha_{\ell})=(1-\lambda)\bigl(1-\alpha_{\ell}\,\theta(\lambda)\bigr),

BLOCK 40 [S2.SS3.p2.2] II-C Laplacian-LoRA Operator
where \theta(\lambda)\in(0,1) is a smooth learned function. The correction strength is depth-annealed according to

BLOCK 41 [S2.Ex9] II-C Laplacian-LoRA Operator
\alpha_{\ell}=\alpha\,\frac{\ell}{L},

BLOCK 42 [S2.SS3.p2.3] II-C Laplacian-LoRA Operator
so that early layers remain close to standard GCN propagation while deeper layers receive stronger contraction weakening.

BLOCK 43 [S2.SS3.p3.1] II-C Laplacian-LoRA Operator
The GCN and Laplacian-LoRA branches are added, yielding the effective filter

BLOCK 44 [S2.Ex10] II-C Laplacian-LoRA Operator
g_{\text{eff}}(\lambda;\alpha_{\ell})=(1-\lambda)\bigl(2-\alpha_{\ell}\,\theta(\lambda)\bigr)=(1-\lambda)\bigl(1+\beta(\lambda)\bigr),

BLOCK 45 [S2.SS3.p3.2] II-C Laplacian-LoRA Operator
with \beta(\lambda)=1-\alpha_{\ell}\theta(\lambda)\geq 0 .

BLOCK 46 [S2.SS3.p4.1] II-C Laplacian-LoRA Operator
By construction,

BLOCK 47 [S2.Ex11] II-C Laplacian-LoRA Operator
|g_{\text{eff}}(\lambda;\alpha_{\ell})|\geq|g_{\text{GCN}}(\lambda)|,

BLOCK 48 [S2.SS3.p4.2] II-C Laplacian-LoRA Operator
implying weaker per-layer contraction and delayed oversmoothing, while stability is preserved as long as

BLOCK 49 [S2.Ex12] II-C Laplacian-LoRA Operator
\sup_{\lambda\in(0,2]}|(1-\lambda)(1+\beta(\lambda))|<1.

BLOCK 50 [S2.SS3.p5.1] II-C Laplacian-LoRA Operator
Since the modulation is diagonal in the Laplacian basis, the resulting operator corresponds to an additive low-rank correction in node space when restricted to leading eigenvectors. Thus, Laplacian-LoRA can be viewed as a LoRA-style residual adaptation anchored to the graph spectrum.

BLOCK 52 [S3.p1.1] III Implementation Details
We evaluate Laplacian-LoRA on five node classification benchmarks: Cora , Citeseer , Pubmed , CoauthorCS , and CoauthorPhysics . For citation networks, we use the standard Planetoid splits, while for coauthor graphs we use the official PyTorch Geometric splits. All models follow a standard GCN architecture with depths L\in\{2,4,8,16,32\} , hidden dimension 64 , ReLU activations, and dropout rate 0.5 . No batch normalization or residual connections are used in the backbone. Models are trained with Adam (learning rate 0.01 , weight decay 5\times 10^{-4} ) for up to 200 epochs, with early stopping based on validation accuracy (patience =50 ). Results are averaged over five random seeds. For each dataset, we precompute and cache the top k=64 eigenpairs of the normalized graph Laplacian using partial eigendecomposition. Laplacian-LoRA is implemented as a shared residual branch applied at all hidden layers. The spectral modulation function \theta(\lambda) is parameterized by a two-layer MLP with hidden dimension 32 and sigmoid output to ensure bounded corrections. Oversmoothing is analyzed by measuring node embedding variance as a function of depth. All experiments are implemented in PyTorch Geometric and run on a single NVIDIA A100 GPU.
