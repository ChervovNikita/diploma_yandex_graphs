# Actual 18.77 BUDDY launcher v3: runtime boundary repair

This is a source-only operational wrapper for the sealed BUDDY v5 family. It preserves the scientific implementation, five arms, seeds 0/1/2, 100 epochs, 15 cells, 24 optimizer fits, four CPU threads, two physical GPU UUIDs, one exact qualified cache, and explicit checkpoint `weights_only=True`. It does not provide heldout scoring. No Torch, model, tensor, archive, GPU, remote command or active-job action was executed while preparing this packet.

V2 and its partial family stay intact. The authentic root custody receipt excludes both prior partial fits from scientific contrasts and preserves outputs, logs, checkpoints, costs and failures. V3 checks the fixed custody, pause and own-process termination receipt hashes in CONTRACT.json. It reuses the unchanged v2 resource pass as a timing/memory observation under the original scientific/runtime identities. That resource observation does not certify a write boundary.

## Fresh paths and boundary evidence

Scientific outputs use the exclusive `root_family_v2/` namespace. A pre-existing family directory blocks execution. Runtime directories use the separate `root_runtime_v1/`, so CPU/data-free boundary qualification can prepare them before admission. Existing canonical runtime directories may be reused; they are never deleted or cleaned by this launcher.

Process-local TMPDIR/TMP/TEMP, XDG cache/config/data, Torch home/extensions/inductor, Triton, CUDA cache, Matplotlib, Numba and Python bytecode paths are canonical inside the actual repository. Bytecode writes and CUDA cache are disabled as well. These values are applied before the context's Torch subprocess and inherited by the unchanged family launcher. Inherited writable regular-file descriptors are checked through Linux metadata before any scientific child. Symlink traversal and outside writable regular-file targets are rejected.

Environment/path checks do not establish kernel write enforcement. `environment_and_explicit_repo_paths_only` honestly records that scope. `external_namespace_profile_bound` requires exact BUDDY_NAMESPACE_POLICY_PATH and BUDDY_NAMESPACE_PROOF_PATH environment variables from the separate namespace guard. The static policy and sealed guard source are prebound in root admission, along with an actual root qualification receipt. The current execution proof is generated by the guard, binds the exact launcher argv, and is hashed at launcher entry. Its user/mount/PID namespace IDs must match the running launcher. Its fresh SHA is not required prospectively. All seven guard certification fields are checked, including readonly outside mounts, writable repository bind, private propagation, fresh private PID/proc, closed extra inherited descriptors, zero capabilities and no-new-privileges. V3 records external evidence; it does not itself certify those kernel properties.

## Root admission and launch

Root owns preservation, stop/termination, boundary qualification and restart. After actual runtime boundary qualification, root writes a separate canonical repository-local admission with schema `buddy77-runtime-boundary-repair-admission-v1` and decision `admitted_fresh_family`. CONTRACT.json lists its identity, receipt and external fields. The admission includes the exact v3 wrapper manifest SHA, predecessor v2/source/cache/CPU/data/resource hashes, old and fresh family namespaces, fixed dimensions/UUIDs/thread count, exclusion/preservation/termination booleans, `heldout_metrics_inspected:false`, the chosen `runtime_boundary_mode`, and a nonempty `root_runtime_boundary_decision`. Custody, pause and termination are distinct canonical JSON paths with their fixed hashes. This packet does not author an admission.

`root_family_v2/RUNTIME_ENVIRONMENT.json` records admission hash, path values, FD metadata, boundary mode and current external evidence.
