# Trained shared-message inference comparison

This companion study measures deployment cost at the weights produced by the complete fixed 30-fit study. It changes neither training nor checkpoint selection. The primary comparison uses the final epoch; the validation-selected checkpoint is a separate secondary result. All two tasks, three seeds, both checkpoint roles and all timings must be retained.

## Fixed design, before quality results

Tasks are complete Reddit2 and ogbn-products, in that order. Seeds are 17, 29 and 43, in that order. For each task and seed, compare exact-member packed inference, exact-member serial inference and shared-mean packed inference. Exact modes load identical exact-member weights; shared inference loads that cell's own shared-mean weights. The two methods must never be described as having identical predictions or weights. Role order is final then selected, even when the checkpoint files coincide.

The implementation reuses the sealed `shared_message_quality_v3.models` constructors and pooled inference functions, complete input lineage, prepared graph operator and scientific runtime. FP32, no AMP/TF32, dropout disabled, four CPU threads and the sole authorized A100 remain fixed. Packed exact is qualified for evaluation only. Products packed noncheckpoint training remains infeasible under the existing 60 GiB cap.

Before timing, compare complete-node pooled logits from exact packed and serial execution at atol=rtol=1e-5. Record maximum absolute discrepancy and class-decision disagreement. Failure disqualifies the computational comparison; do not loosen tolerance. Shared predictions are not expected to equal exact predictions. No targets enter a forward or timing operation. Input acquisition may materialize its already exported training targets; validation and test target files must not be opened by the benchmark.

Each checkpoint role has five warm-up forwards per mode and 50 paired rounds. Each round executes all three modes. Create a fixed balanced order by repeating all six permutations eight times, adding the first two permutations, then shuffling the 50 rounds with `random.Random(917000 + 100 * task_index + seed + 10000 * role_index)`. Synchronize CUDA immediately before and after each full-node forward and raw-logit pooling. The timed region excludes graph setup, checkpoint loading, byte hashes, output comparison and CPU copying; report those exclusions and the complete supervised wall separately. Include all samples, arm order, medians and p90 values. Choose the stronger exact deployment comparator using the smaller median of the two exact modes, independently of quality. Report shared reduction against each exact mode and the stronger comparator. Do not infer training gains from deployment timing.

All modes use the same resident graph and both model objects. Report that common-residency convention. For each mode, measure an additional isolated-forward peak after clearing the CUDA cache and resetting peak counters, with no other output live. Report baseline allocated/reserved bytes and total forward peak allocated/reserved bytes. A 60 GiB reserved-memory ceiling applies throughout. Resident graph storage, weight bytes and setup/loading wall are reported separately. Checkpointing must stay inactive in eval/no-grad; do not change model flags to create a different implementation.

## Evidence and admission

Execution is blocked until the full scientific family and all 30 replays have completed and the family lock passes its existing consumer audit. That audit may parse existing score metadata for integrity; it is not a new evaluation or a source of checkpoint choice. Preserve exact checkpoint byte references, input/operator lineage, source closure, runtime, GPU UUID, inner and outer supervision, all samples and failures. Do not save new predictions when numerical comparison summaries suffice.

Use six fresh bounded children, one per task/seed, with a maximum 600 seconds per child and five seconds of termination grace inside that cap. No overlap with the running scientific queue, no retries or automatic resource amendments. Reserve at most 3600 seconds for the companion, 64 MiB of new artifacts and four CPU threads per child. The scientific phase's combined 21600-second wall budget and 200 GiB disk cap must still hold after charging prior work, the completed scientific family and every companion child. Refuse before launch when a full remaining child cap cannot fit. Source preparation alone does not authorize execution; independent source audit and a separate root-approved request are required.

No novel mechanism, quality retention, predictive superiority or training benefit follows from this benchmark. Those require the complete audited validation family, relevant efficient comparators and held-out confirmation.
