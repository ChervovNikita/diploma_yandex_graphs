# New tasks for post-submission research (2026-09-30)

This is an exploratory research proposal. No model was trained or scored. The submitted benchmark and text were not changed. Development archives for MolHIV and PPI were downloaded inside this folder only to check source bytes, graph sizes and official splits. Confirmation datasets were not downloaded. Published baseline scores are literature context, not our confirmation results.

## Recommendation

Use **MolHIV, PPI and MNIST superpixels** as the three immediately practical development datasets. Their graph-level scaffold prediction, inductive multilabel node prediction and image-derived graph classification test different failure modes. **MalNet-Tiny** is a useful additional real graph task for the efficiency branch, conditional on recovering the official data and split endpoints. **GOOD-Motif** is an optional published synthetic mechanism test of shortcut learning, rather than evidence of real-world robustness. Keep **Peptides-func** and **GOOD-CMNIST** untouched until the method/protocol freeze; CIFAR10 superpixels is an optional confirmation of the sparse mean efficiency branch.

There are two architecture branches: chemical data require bond-aware GINE; sparse mean SAGE can serve PPI, MalNet-Tiny and MNIST. Do not use bond-blind SAGE as the main molecular competitor to make branches uniform. All comparisons within a task use the same input features, edge conventions, graph readout, loss, and model-selection budget.

## Concrete hypotheses

**H1: Sharing acts as a useful regularizer under scarce graph supervision.** With fixed graph features/topology, a shared propagation stack might reduce the variance of learned transformations while distinct boundary projectors retain useful member differences. Predict that TIED-minus-copied-UNTIED is more favorable with 10% of the official training labels than with 100%, on both MolHIV and PPI, and that this occurs without a deterioration of validation proper loss. Prespecify nested training-label subsets; retain the entire official validation/test sets. On PPI, select nodes per training graph and reveal all 121 targets for each selected node; do not sample individual label entries and change missingness. On MolHIV/MNIST, select training graphs stratified by their training labels. These budgets are two conditions on one dataset, never two independent datasets. If benefits only appear on one selected corpus or only after more tuning, stop the general regularization claim.

**H2: Sharing alone does not ensure invariant propagation.** Members can share the same spurious shortcut. GOOD-Motif basis/concept supplies explicit environments and known motif/edge rationale annotations. Predict that ordinary GNNM can retain high ID accuracy with poor OOD accuracy despite member disagreement. Treat this as a discriminating test against stronger invariant-learning methods, not a venue for tuning until a desired gain appears. MolHIV scaffold performance is a real generalization test, but scaffold ROC-AUC alone does not establish causal invariance or OOD detection.

**H3: Separating common and narrow member paths can improve actual compute.** Unlike the original model's four separate hidden-state propagation paths, a common-plus-narrow SAGE implementation must be evaluated with its actual sparse operations and measured latency/memory. PPI and MalNet have larger graphs than molecular samples; MNIST supplies many small batches. Prediction: a fixed exact algebraic factorization, if it preserves logits/gradients as claimed by its own preflight, will show different savings in the larger-graph and small-graph regimes. Do not infer savings from stored parameter counts. This note does not independently verify the coordinator's efficiency implementation.

## Candidate objective change and novelty boundary

One low-cost candidate is **environment-robust member risk** on the GOOD mechanism branch. Let R[g,m] be mean CE of member m on training graphs from released environment g. Replace ordinary mean-member ERM with

`L = tau * log(mean_g exp(mean_m R[g,m] / tau))`.

Implement stable logsumexp; sample each training environment in every batch or use explicitly logged unbiased group-risk estimates. Predict that robustness-aware shared updates reduce the worst-environment validation loss at comparable ID accuracy, if training environments contain enough useful variation. Pool logits as before. This adds no model parameters and no additional propagation paths; group losses add O(M*batch) arithmetic. It may fail when all training groups share the same shortcut, as the .99/.97/.95 setting makes plausible.

**This objective is an established smooth group-DRO construction, not a claimed new optimization principle.** Compare (i) member-risk versus loss of pooled logits, (ii) TIED versus copied-UNTIED under each objective, and (iii) a single model with the same group-risk objective. The resulting interaction tests whether sharing helps robust training. Primary candidate grid: ERM plus two fixed temperatures only; charge these three choices to every comparator that can use them. Do not add a disagreement bonus merely because it raises disagreement.

Nearest technical prior search found BatchEnsemble (2020), TabM, graph-specific BatchEnsemble attributed to Kim (2023) in the project README, GroupDRO (2019/2020), VREx (2020/2021), CIGA (NeurIPS 2022), GALA (NeurIPS 2023), and **SuGAr (AAAI 2025)**. SuGAr already trains multiple identically initialized featurizer/classifier GNNs with subgraph sampling and pairwise predicted-edge-weight diversity; it aggregates masks before ensemble prediction and also offers weight averaging for one inference model. A proposal called "diverse invariant GNN ensemble" or "ensemble-to-one weight averaging" would repeat this contribution. Shared propagation with robust member risk is at most a combination/intervention until a graph-specific benefit or analysis is demonstrated. Kim's KAIST endpoint returned a security page; exact title/abstract were not independently verified here. Crossref also indexed 2026 "Invariant Graph Transformer for Out-of-Distribution Generalization" and "Ensemble Graph Neural Networks With Individual Decision Feedback for Graph Classification"; metadata alone is insufficient to claim architectural comparison or novelty clearance. Broad search endpoints were rate limited; novelty review is therefore bounded, not exhaustive.

## First executable pilot and compute

The saved `freeze_development.py` can load/fingerprint MolHIV/PPI/MalNet/MNIST using the existing project environment. It never trains or scores. MolHIV uses supplied discrete graph features, so **RDKit is not required for the loader**; fingerprint RF and molecule-overlap analysis would require it later. Local Python here lacks torch/PyG/ogb, so syntax was checked but loader runtime was not executed. The coordinator should execute first on the allowed original repository, recording that environment's actual provider source and canonical tensor fingerprints. No GPU launch was made.

**Sharing-policy pilot:** MolHIV GINE, width 128, 3 residual layers, mean readout, LayerNorm per node, four members, BCE, AdamW. First fit the initially identical TIED/copied-UNTIED pair for one prespecified seed/config, capped at 100 epochs, use official validation ROC-AUC for checkpoint selection (validation BCE then earliest epoch as deterministic tie-break), and do not score test. Boundary W/factors and all random states are paired; untying graph stack alone is the intervention. The molecular categorical embedding lookup is shared in this pair and identical initially, and per-layer bond encoders follow the tying policy. Add BASE, ordinary shared-representation/multiple-head control and independent ENS before making a complete-method efficiency or ensemble claim. The attached YAML locks proposed choices. Chemical adapter normalization must receive graph batches correctly if GraphNorm is ever used; the snapshot GraphNorm wrapper currently omits the batch argument, so use LayerNorm initially.

**Efficiency pilot:** PPI sparse-mean SAGE on fixed directed non-loop adjacency, width 128, 3 layers, four members, batch one graph, 10% labelled training nodes and BCE. Run BASE/TIED/copied-UNTIED/common+narrow plus shared-representation head control with identical label masks/batches and pooled validation micro-F1 selection. Validate initial logits/gradients before fits where functional equality is claimed. GAT/GCNII reference runs come after this preflight. Preserve the original current-model architecture as a separate comparator if the common+narrow architecture changes nonlinear processing.

## Provenance and stopping rules

Raw SHA256s and official split hashes are retained in `sources/dataset_metadata/`; `DATASET_MANIFEST_PROPOSAL.json` distinguishes verified archive facts, published metadata and unverified intended freezes. The freezer additionally retains raw and processed file hashes, actual provider source, package versions, feature rules, canonical per-graph x/pos/edges/edge_attr/y fingerprints, aggregate split hashes, and train/val counts only. Test tensors are hashed without class summaries or scoring. No confirmation data is accessed by the freezer.

Before any score: pin source Git commit and trainer hashes, environment/precision/seed state, data/loader hashes, masks, graph readout, normalization, optimizer, stopping/checkpoint rules, arm definitions and all candidate budgets. Freeze selected development recipes before adapting to confirmation; protocol adaptation can use confirmation train/val under a prospectively fixed budget but cannot inspect confirmation tests. Preserve failed attempts. Repeated seeds estimate optimizer variation on one dataset. If a claim requires broad independent-dataset significance, this small suite is a pilot, not sufficient evidence. Continue only if a measured quality/storage/runtime advantage survives matched baselines on multiple independent corpora; otherwise report the limit and stop expanding a winning configuration.
