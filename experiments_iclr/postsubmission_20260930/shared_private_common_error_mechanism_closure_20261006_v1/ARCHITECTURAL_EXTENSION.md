# One private propagation capacity hypothesis

**Conditional candidate:** give each member independent parameters for exactly the **last existing native local propagation block**. Retain the preceding shared blocks, member-dependent stem paths, native global attention, public graph, operator, depth, boundary factors and arithmetic probability pool. No new edge mask, graph prior, loss weight, sign transport or meta-credit term is proposed. This is a known shared-bottom/private-top architecture adapted to the current parameter ownership, not a new principle.

## The missing operation is private message learning

In the current source, every local propagation block's dense message, attention/channel and gating parameters belong to the shared core. The members have different activations because their private stems act before complete nonlinear graph trajectories. They do not have independently trainable native local blocks.

The proposed last block would instead have one complete parameter set per member, including its source-defined affine/gating/normalization parameters, with the old shared block removed from trainable ownership. Ordinary private learning could then change a member's neighborhood processing rather than only the stem and output projectors. Copying the original block into all members before acquisition can preserve the exact starting predictions; source qualification must check that equality, ownership and native optimizer initialization. There is no delayed unsharing of a trained block with silently reset moments.

This relaxes a concrete parameter-tying constraint at a fixed layer. It does not prove that the current architecture has erased raw graph information or that its whole function class cannot emulate the new computation. The same native evidence and operator are used. If missing information is outside all retained paths, or the useful distinction requires a stronger operator, private copies of this block will not recover it. Return-message, nonbacktracking and distributional-information remedies already have saved priors; they are not silently added here.

## Why the fixed pool cannot supply this operation

For one target y and common competitor k, if p_m(y)<p_m(k) for every member, then their probability mean also satisfies p_pool(y)<p_pool(k). Pooling those fixed predictions cannot repair that common ordering. This statement concerns one common competitor; members choosing different wrong classes can sometimes be repaired by pooling.

Private propagation can change the predictions before pooling. The hypothesis is that the shared last kernel currently averages incompatible useful neighborhood-processing demands, and a fully trainable private last block can make competent corrections that the projector-only ownership does not learn within its budget. No current prediction or state evidence diagnosing that failure was opened. The capacity hypothesis is falsifiable and may simply fail through redundant kernels, overfitting or continued common bias.

Sharing the earlier blocks could pool supervision for stable low-level graph features while the private blocks handle different higher-level combinations. This could reduce estimation noise relative to four independently acquired encoders. Independent encoders have more freedom and can also learn these combinations; no superiority follows from sharing alone. Several competent private blocks could cover different correctable patterns better than one native predictor, but a capable single with the same information and sufficient late-stage capacity may match. If so, keep the architecture benefit and simplify. A complete branched bank can itself be viewed as one nonlinear predictor, so an ensemble-only capacity claim is unavailable.

## Closest prior and previous work

**TreeNets**, Lee et al., arXiv1511.06314v1, inherited §5 in the saved adaptive-sharing assessment, is the strongest consulted structural prior: same-task ensembles share initial layers and vary branching points. Untying an upper block is therefore not a discovered architectural principle. **CAMERO**, arXiv2204.06625v1, inherited §3.1, supplies shared-bottom/private-top supervision and sharing-quality ancestry. Its BERT serving example uses one encoder and private classifiers; it does not certify useful member-private graph propagation here. Perturbation/consistency terms from CAMERO are not imported.

The genuinely missing operation in the current source is the independent native message-processing parameter block. Its ordinary learning could be useful despite that ancestry. The saved private-frame and completion dispositions address different operators/tasks and do not falsify this particular capacity change. Conversely, previous private filters, quantile branches, graph views and adaptive-unsharing proposals prevent claiming that private structural processing or choosing what to share is new. No exact local trial of this one-block modification was established from the consulted decisions; that is a local bookkeeping boundary, not historical novelty evidence.

The strongest capable mechanistic comparator is **four untied encoders using the same private-block operation and ordinary objective**. It contains the candidate's representational opportunity and tests whether retaining earlier sharing helps quality. Competent source-native single and truly independently acquired four remain the essential practical quality references; the single must have the full native propagation/nonlinear learner, not a projector-restricted head.

## Compute boundary

Let p_last be the source-defined number of trainable parameters in the complete last local block. Replacing one shared copy by four private copies adds 3p_last parameters, or **12p_last bytes of FP32 weights** with clean ownership. Any inactive source padding must be counted separately. Gradients, optimizer state, snapshots and allocator overhead add more. This is a parameter-storage floor, not a measured memory bill.

The present family already evaluates four complete member trajectories. This change introduces no additional graph layer or per-member forward pass; it changes parameter ownership and gradient/optimizer work. Faster execution, fitting time and peak memory are unmeasured, and old higher-order qualification peaks cannot be imported as a budget for the changed architecture. Candidate and matched untied fits require new source/runtime qualification. No GPU allocation is requested now. If root elects this screen, the complete fit, qualification and acquisition bill must first be measured or prospectively capped; no automatic cap expansion or launch follows from this conditional proposal.
