# Two-graph native engineering wrapper — source only

Prepared for root review. Nothing has been staged, dispatched, imported numerically or loaded from graph/checkpoint arrays. The sealed native runner has an independent source review with no concrete blocking source defect; actual runtime/operator/state/cost qualification remains untested. Scientific continuation is disabled.

`stage_client.stage()` stages only the exact sealed runner and selector packages, frozen constants, eight bound native source modules and wrapper/descriptor metadata. It stages no arrays, checkpoints, installed packages or scientific outcomes. It uses the fixed authorized SSH account/port/key, checks the sole UUID before project-file operations, verifies bytes and refuses differing overwrites. `stage_client.launch()` is a separate explicit call. The client CLI only prints preparation status. Root must inspect this wrapper before either operation.

The launcher verifies the authorized destination/project and sole UUID, records the current Unix identity, writes an exclusive once-only guard and starts one owned detached supervisor. The supervisor runs Squirrel17 then Photo17 in separate owned process groups. Each uses the repository `.venv/bin/python -B`, full fresh prescribed native warm and disposable qualification checks; there is no old-warm input or predictive continuation call. The existing bound original graph/role/compact-label bytes are verified by the reviewed runner at execution, inside the child cap.

Each graph requires at least **32768 MiB (32 GiB) currently free GPU memory**, queried immediately before child creation and checked again before numerical import. This is the prospective conservative headroom policy; it is neither a measured method requirement nor a capacity guarantee. A failed floor blocks the sequence without waiting or retrying. Co-resident work is allowed; no idle-GPU requirement, other-job inspection or signal is used.

CUDA policy is common to both: visible device0, CUBLAS `:4096:8`, deterministic algorithms, TF32 disabled for matmul and cuDNN, highest FP32 precision, OMP/MKL threads1. Outputs, logs, temp and relevant framework caches remain in the project-local execution folder. There are no filesystem namespaces or host changes.

**Budget:** one child attempt per graph, at most **3600 seconds each /7200 seconds total engineering execution**. Data loading and numerical setup are inside the child cap. An exceeded cap is retained as failure; the supervisor signals only its created child group, with at most5s TERM grace,5s KILL grace and5s final parent-reap wait per graph. A remaining owned group or unreaped parent stops the sequence and is reported unresolved. Native/preflight failures are retained, including failures before the runner can emit its own report. A graph-specific qualification failure may be followed by the other graph only after source custody, physical closure and its fresh memory preflight succeed. No graph is retried automatically.

Receipts include launcher/supervisor/child PIDs and PGIDs, source hashes, GPU snapshots, CUDA policy, logs, per-graph cap/exit/closure and wall/CPU/RSS metadata, plus the reviewed runner's detailed qualification/cost report. Supervisor RSS is labeled as cumulative child high water. Staging and preflight overhead are outside the one-hour native child caps. An unknown SSH launch outcome must be inspected through the once marker and receipts; it must never trigger another launch.

Proposed execution folder: `graph_curvature_selector_native_engineering_execution_20261004_v1` under the authorized server phase. This source preparation creates no such remote folder.
