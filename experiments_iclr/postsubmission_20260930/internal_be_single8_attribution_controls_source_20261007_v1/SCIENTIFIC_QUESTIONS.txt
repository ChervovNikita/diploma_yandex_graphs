Prospective single-backbone, eight-view attribution controls
==========================================================

Scope decided before implementing the optional third control
----------------------------------------------------------
This is local source preparation. No source import of a numerical framework,
model construction, dataset/score/checkpoint read, server/GPU operation,
release, adoption, training, family extension or publication follows from it.
The public V2 interface and frozen core, main Wiki24 and first portable families
remain unchanged. Execution stays postponed until the candidate merits an
unused confirmation experiment and a separate fixed family is adopted.

The source shared BE update has four persistent member RNG streams, each used
twice, eight full supervised paths and one shared Adam update. Ordinary single
uses two full views. Counting optimizer steps alone therefore does not match
the stochastic supervised work. The controls below match eight supervised
views per update with one ordinary native body, no rank-one private factors,
one optimizer and deterministic single-body inference. They match view count,
not wall time, peak memory, parameter count or inference ensemble opportunity.

1. single8_own
   L = (1/8) sum over four streams and two views of the unchanged task own loss.
   No auxiliary target. Paired against ordinary single, this asks whether more
   stochastic loss averaging changes performance at the same number of Adam
   updates, labels, batches, model parameters and selector opportunities.
   Repeated views do not add unique labels or independent observations.

2. single8_alignment
   L = L_own8 + 0.05 * A, where A is the unchanged core alignment_loss over
   [four streams, same bounded object subset, representation dimensions].
   Its reduction is the mean of each stream's symmetric two-view alignment.
   No cross-stream/member residual term. Paired against single8_own, this asks
   what the declared alignment target adds with eight views held fixed.
   single_contrastive is the source two-view/M1 alignment control: its residual
   term is identically zero. Eight-versus-two alignment remains a compute and
   Monte Carlo variance comparison, not more labels or architecture diversity.

3. single8_virtual_contrast -- optional, explicitly attributed extension
   L = L_own8 + 0.05 * A + 0.05 * R. R is the unchanged M4 class-centered
   residual_member_contrast, with RNG streams substituted for member channels.
   Same-stream/object across the two views is positive; other RNG streams of
   the same object are negative. All four outputs share every parameter of
   one body and are supervised; no private factors, head, projection bank,
   per-stream input feature or stop-gradient is added. The four stream seeds
   are persistent stochastic identities, not learned ensemble members.

   This asks whether the full objective can regularize stochastic paths of
   one parameter body without retaining four inference predictors. Relative
   to single8_alignment it attributes the added residual proxy in this shared
   body setting. Relative to BE contrastive, it controls view count, auxiliary
   weights/targets and one optimizer update, but private parameters,
   initialization and mean-member serving still differ. It cannot by itself
   isolate internal placement, parameter capacity or ensemble necessity.

   The stream distinction can disappear when dropout is disabled at inference.
   A representation residual proxy is not mutual information, useful prediction
   diversity, preserved class information, or proof of a new objective. Class
   centering does not preserve class means through different parameter
   Jacobians. Deliberately increasing stochastic variation may hurt inference.
   The control is an optional stochastic-control extension, not a renamed BE,
   a new architectural ensemble, or an inferred winning recipe.

Known priors and attribution
---------------------------
Multi-view own-loss averaging is a standard Monte Carlo gradient-estimation
control. Two stochastic/dropout views and consistency/contrastive learning have
known precedents (supervised contrastive learning, GRACE, SimCSE and R-Drop).
Those names denote prior ideas, not claims to reproduce their exact losses:
this source uses the existing label/identity alignment, not R-Drop's KL loss.
WikiCS and Molhiv use same TRAIN class as alignment positives; molecule binary
classes are coarse and are not chemical equivalence. Collab alignment uses the
canonical TRAIN target edge identity, not same binary labels as equivalent
edges, and rejects contradictory labels for a canonical identity.

The residual term is the suite's CDLG-inspired class-centered cross-channel
proxy, motivated by conditional-redundancy ideas such as DICE; it is not a DICE
implementation or an MI estimator. BE maps remain attributed to BatchEnsemble
and first-factor/own-member learning to TabM. None of these controls establishes
novelty, causal graph evidence, or acceptance-level confirmation on its own.

Selector, populations and custody
--------------------------------
Reuse public V2 Session construction/core losses/data iterators, evaluate,
joint_snapshot and full train main. No copied epoch driver. Source strict first
maximum of the complete unrounded VALID metric stays unchanged; no early stop,
individual view selector or stochastic inference averaging is introduced.
WikiCS retains the 100-local/1000-global transition: restore selected joint
local model/optimizer and keep live end-local RNG streams. Snapshot metadata
adds the four training-view states but exact resume stays unsupported, as in
the public full driver. All active gradients, predictions, parameters and Adam
state retain the source finite checks. Any failure preserves the output and
gets FAILURE.json; there is no retry, subset, alternate seed or rescue path.

WikiCS: complete split0 TRAIN 580 and VALID 5274, complete 11701-node graph,
1100 epochs, one update each. Collab: all 1179052 official TRAIN event records
through 2017, 60084 VALID positives in 2018 and all 100000 authentic negatives,
including the one negative self-pair; 100 epochs, 18 updates each. No validation
pair filter is added to past support. Molhiv: all 32901 TRAIN and 4113 VALID
graphs, original atom/bond fields and scaffold split, 100 epochs, 258 updates.
Auxiliary objects are capped at the same deterministic 512-index selection;
all own-supervision objects remain complete in every one of eight views.

No performance, numerical parity, runtime suitability or speed claim follows
from AST/source checks. These controls need a separately authorized real-data
qualification if execution is later warranted. No micro-parity or synthetic
performance gate is proposed here.
