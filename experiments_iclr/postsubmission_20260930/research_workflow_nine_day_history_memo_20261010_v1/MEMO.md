## Measured bottleneck versus proposed cause

Some unchanged shared banks have almost no available alternatives on their remaining errors and strict common false rivals. Reweighting those unchanged probabilities cannot repair the witnessed rankings. Other banks, including I4 and specialist treatments, have available alternatives that the pool loses. There is no single universal bottleneck across all banks.

We have **not** established that negative auxiliary-gradient products, harmful shared Adam displacements, missing topology, hidden nullspaces or calibration caused the observed deficit. The raw-gradient projection triage is a distinct known-method control, with coefficient and Adam confounds still unresolved. Such explanations should remain falsifiable hypotheses rather than reasons to start another bespoke integration.

The archive supports this scientific assessment, not a precise allocation of all nine calendar days between engineering and research. The workflow cost that can be reduced is repeated integration around each new recipe: constructor changes, specialized gradient paths, owners, restoration and readers introduce additional failure opportunities before a comparative result exists.

## Three concrete next decisions

1. **Choose one portable intervention for the common wrapper and a small fixed roster of already supported backbones/tasks.** Reuse existing data, training, serving, checkpoint and finite-owner paths. Express the intervention at one declared common interface; preserve each backbone’s native behavior elsewhere. Defer configurations requiring another bespoke runtime or architecture port. Perform the necessary integration checks once for that interface, then complete the fixed study.
2. **Put capable references in that same study from the beginning.** Include the factorized single, genuine independently acquired I4, unchanged shared baseline and candidate under the same wrapper. Preserve declared independent selector/capacity differences and the task’s serving rule. Use the frozen criteria; report per-seed accuracy/NLL, mean/worst members, exact acquisition/coverage loss and served repairs/harms. A gain over a weak reference must not become the headline.
3. **Make one whole-family advance-or-close decision.** Use cross-backbone results to identify where the same intervention transfers and where it fails; do not change recipes after partial outcomes. If it survives capable references, prioritize unused confirmation before more ablations. If it fails, retain the result and stop that recipe’s grid. Existing stored-error diagnostics can clarify the failure without becoming a new week of mechanism-specific infrastructure.
