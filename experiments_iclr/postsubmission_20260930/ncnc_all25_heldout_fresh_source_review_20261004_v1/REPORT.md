## Concrete source blockers

**B1 — A bounded supervisor stop can leave no all25 terminal closure.** In `supervise_heldout_once.py:166`, timeout or RSS excess sends SIGKILL. The supervisor later writes only `PHYSICAL_TERMINAL.json` (`:210`–`:231`). It does not synthesize the protocol's all25 statuses, null TEST metrics, null summary, and interrupted work disposition when `HELDOUT_RESULT.json` is absent. The child's `except Exception` (`heldout_run.py:154`) cannot handle SIGKILL; early import/admission failure also precedes the child's result-writing block. `STATUS.json` exposes counts but no cell list. Further, the entered-scorer count is incremented without persisting it immediately before the call (`:123`), so a kill during scoring leaves an older count on disk. A physical failure receipt alone does not satisfy the promised all-cell failure/accounting endpoint. Minimum repair: let the supervisor produce an explicitly failed, all25, null-metric closure when the child cannot, carrying persisted counts as observed lower bounds and naming any uncertain in-flight work; persist entry events before scorer entry. Preserve the claim and never retry.

**B2 — A failed metric cell is reported as NOT_ATTEMPTED.** After the final scorer for a cell validates, `current_slot['validated']` is true (`heldout_run.py:135`). If pooling or `strict_hits50` raises (`:140`–`:143`), the exception branch marks a cell failed only when that flag is false (`:157`–`:159`). The affected cell therefore retains its initial `NOT_ATTEMPTED` status although all its scorer members ran and its metric failed. The overall result correctly fails and nulls metrics, but the per-cell failure record is false. Minimum repair: track the current cell phase independently of the last member's validation flag and record the failed pooling/metric phase. Distinguish a metric attempt from a returned, validated official metric if both are reported as counts.
