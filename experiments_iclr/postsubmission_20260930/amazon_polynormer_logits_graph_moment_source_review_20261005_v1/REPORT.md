## F1 — Native single accuracy uses softmax argmax instead of the original raw-logit argmax

**Priority: P1; source-contract mismatch.** Original V6 `evaluate.py:91` defines the one-member native prediction as `z[0].argmax(-1)`; only the four-member predictor uses `softmax(z).mean(0).argmax(-1)`.

New `numerical.py:46–50` creates `native_class` from FP32 softmax probabilities for every bank size. `study.py:187–190` and `209–213` pass that class vector to raw-native metrics, including the member0 single alias. Thus source V1 can report a different native single accuracy from the source-bound original evaluator.

FP32 softmax can round distinct top logits to equal probabilities; its smallest-index argmax can then differ from raw-logit argmax. A synthetic vector such as `[0, 1e-8, 0, 0, 0]` is a useful root qualification case, **not a numerically executed or observed target result in this review**. The discrepancy can affect the native-single diagnostic and the bank-versus-native-single interpretation; its frequency in the actual saved bank is unknown.

**Required narrow repair:** retain `native_class` as the graph mask reference, since the frozen V2 single graph explicitly uses FP32 softmax argmax. Add a distinct native-scoring class: raw FP32 `z[0].argmax(-1)` for one member, native FP32 mean-probability argmax for four members. Use that scoring vector only for uncorrected native accuracy in fold and aggregate metrics. Keep the stable FP64 native NLL/Brier, graph mask, scientific constants, operators and gates unchanged. Preserve V1 and bind the repair in a new source version.
