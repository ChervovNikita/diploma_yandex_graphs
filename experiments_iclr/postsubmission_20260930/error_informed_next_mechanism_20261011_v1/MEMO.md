# One bounded ordered-path acquisition diagnostic; no new sharing method nominated

**Disposition:** retain one bounded, inactive acquisition/control question, **not a new shared-backbone ensemble method**. No source, fit, new grid or queue is admitted. It is an attributed PathMLP/Side-Tuning adaptation, with an existing local side-ensemble ancestor. The stronger integrated shared-path implication is unexecuted and not nominated here. Native E4 endpoint-VALUE remains the active method; Penn94 confirmation continues independently.

## Recorded observation

The complete matched SAGE F study gives useful sharing, rather than a universal weak-member failure: raw shared accuracy 80.6219%, versus genuine factorized I4 80.0847% and matched joint untied4 79.9014%. Shared mean members are weaker (78.5062%, versus I4 79.2109%), yet sharing adds 225 covered readouts relative to I4. It loses 141 extra alternatives in probability pooling, adds one aggregation-only answer and serves 85 extra correct readouts. The three-seed totals are 13,731 coverage/976 losses/12,756 served, over the same 5,274 development nodes repeated three times. Its own strict-common-wrong-rival cohort is 1,961 readouts with zero pooling corrections. Calibrated NLL harm versus I4 is +.021448, narrowly above the frozen +.02 mean cap; accuracy remains a positive finding. [E1]

Thus the next question is **additional label-grounded prediction evidence that survives serving, while retaining F's already useful functions**. These observations do not diagnose path information loss, a historical shared-gradient cause, or a general covariance mechanism.

## One acquisition diagnostic and its retention boundary

Keep every selected F parameter, normalization state and deterministic evaluation function frozen. Acquire **one independent full-class ordered-path predictor S** from public X/E and all original TRAIN labels, using ordinary own CE and its own SELECT checkpoint. It neither trains on held error cohorts nor matches F's pseudo-labels. Serve the fixed bank-level mixture

`p_new = .5 p_F + .5 p_S = (1/8) sum_{i=1}^4 p_Fi + .5 p_S`.

Retain S alone as an indispensable same-selected-state readout. The candidate acquires **one label-trained predictor per block, zero independent teacher bank, and no subsequent student/F retraining**. S receives no F targets, probabilities or gradients during acquisition. No learned router, temperature-selected mixture weight, residual target, graph-target dictionary, winner/nonowner loss or feature-repulsion objective is introduced. The trained F bank is an already-paid served predictor. Freezing only its private rows would be inadequate; all common/private weights and running state stay frozen. This exactly preserves its component predictions, **not** the accuracy of the new mixture or the competence of S. The user's rejected independent-teachers-then-retrain design is not reintroduced.

The final candidate has **five prediction routes**: four native F routes and one S route. The four sampled input paths inside S are four observations within one predictor, not four ensemble members. F+I4 has eight prediction routes. These route counts and unequal candidate weights must accompany every accuracy/cost comparison.

The substantive change is S's served observation: nonlinear node encodings are concatenated in **ordered path positions before path aggregation**, following the saved PathMLP mechanism. Its raw-node and native source-backed topology components remain disclosed and equally available to controls. A TRAIN true-class loss directly learns new class rankings from these observations. This is a different input/function family from training-only embedding/key losses. It is also different from E4: E4 transforms each actual one-edge VALUE from live endpoints inside the existing native scalar message operation; this candidate constructs a separate higher-order ordered-path predictor and leaves F's native messages untouched. No claim that either operation is universally stronger follows.

For a single prospective full-graph development screen, use a fixed source-bound compact adaptation: width 128, four label-free paths per node, three node positions per path, 1000 updates maximum/300 stale own-SELECT updates, original proper roles and three paired seed blocks. These are finite proposals, not paper-reproduction defaults. Path selection uses public feature similarity, fixed tie/seed conventions and no labels/predictions; exact low-degree/repeated-position handling must be bound before implementation. No path-length/count/strength search follows outcomes. The graph includes every factual node, including unlabeled nodes; every supervised S update uses all TRAIN labels.

### What a positive diagnostic would and would not establish

S has no shared parameters with F and supplies no gradients to it. The only scientific work performed by sharing in this diagnostic is the **already observed** useful F bank summarized in E1. A gain could establish complementary ordered-path acquisition and fixed serving on top of that bank. It cannot establish a new benefit of common path-encoder gradients, four-route co-adaptation, or a new parameter/compute saving from sharing. If S alone or path I4 explains the gain, the appropriate conclusion is useful path architecture/information; even an unexplained F+S serving gain remains a side-ensemble finding.

A different, stronger hypothesis would insert **one shared ordered-path encoder end-to-end into all four native routes**, with native private factors/heads and ordinary true-label supervision of every route. All four routes would then contribute gradients to shared path parameters, with no independent teacher bank or freeze/retrain stage. That hypothesis would require architecture-matched path single, genuine path I4 and joint untied4 controls to identify what sharing does. It would also reopen member competence: ordinary member CE does not guarantee it, and freezing F no longer preserves its functions once new features alter native route predictions. It therefore cannot inherit this diagnostic's exact retention statement, 18-body bound or results. It remains **unexecuted and unadmitted**, without code, another family, source specification or launch in this memo. Current evidence does not yet justify naming it as a new shared-backbone method.

## Decisive capable baseline and one control

Acquire just three predictor families on one complete encountered development graph:

1. S with real ordered paths; report S alone and the fixed F+S mixture.
2. S_perm with the same path node tuples, widths, active parameters, label exposure, horizon and optimizer, but a label-free public-seed **per-node/per-path fixed swap assignment** of the two non-root positions before both training and inference; report S_perm alone and F+S_perm. The root position is retained. A single global swap is merely a position relabeling and is not an order-destroying control. The per-path assignment scrambles the consistent meaning of non-root positions while preserving node observations; retraining allows the control to exploit any recoverable ordering. It does not isolate all path/topology contributions, and raw-node/topology branches may partly recover that information.
3. **Genuine same-information path I4:** four complete independently initialized/acquired/own-selected copies of the full union-view S architecture, disjoint parameters and optimizers. All use the same label-free path tuples within each paired block. Its standalone pool is the capable ensemble reference; the equal bank-level 50/50 policy in F+I4 prevents giving only the candidate the frozen-bank mixture. The ordinary S single is the strongest exact architecture/input-matched M1 reference. Historical ordinary/factorized native M1 and I4 remain visible as context, rather than substitutes for these new same-information controls.

There is one mechanism and one order control, not a coefficient/architecture grid. No different private path cohort assignment is added. No ANN/teacher fitting or endpoint-VALUE arm is added. If S alone or same-information I4 explains the gain, report useful architecture/evidence acquisition without an ensemble-specific or sharing gain. An evaluation-only shuffle of a selected S is not the required retrained control.

**Primary diagnostic question:** does F+S improve net served full-role accuracy over F and F+S_perm? The stronger complementary-serving claim additionally requires superiority to capable S/I4 readouts; comparison with equal-policy F+I4 discloses the extra independent-route explanation. A success against those controls still supplies no new causal sharing result. Raw/calibrated NLL/Brier tradeoffs remain explicit. Root fixes practical margins, calibration cost/roles and the paired inference contract before any future acquisition. Three seeds here are a developmental comparison, not another unused-confirmation claim or node-iid sample.

Report mean/worst/per-seed S quality separately. Frozen F's predictions cannot degrade and union oracle coverage cannot decrease when S is added; weak S, changed pool accuracy or proper-risk harm remain possible. Require actual new S-correct predictions on the **fixed F strict-rival and all-member-wrong cohorts**, how many are served by F+S, new served rival errors, old F-covered cases lost by the new serving, repairs/harms and classes. Also distinguish repairs of already-covered F pooling losses from genuinely new alternatives; overlapping repair descriptions are not exclusive causes. Count full-population harms, not only favorable cohorts.

For each rival r, the fixed mixture needs `p_S(y)−p_S(r) > p_F(r)−p_F(y)` to correct its margin. Every rival must be beaten. This shows what the new predictor must supply; ordinary own CE, ordered paths and preserved F do not guarantee it. More path separation, oracle coverage, hidden distance or TRAIN fit alone fails the hypothesis.

## Representative finite compute and disposition

The proposed three-seed screen has **18 new complete body fits**: three S, three S_perm and twelve path-I4 bodies. There are six new fits per block; four I4 bodies are capable controls, not teachers. At 1000 updates the screen requests at most 18,000 optimizer steps/backwards, 18,000 TRAIN and 18,000 SELECT full-graph path-predictor passes plus 18 selected path-body readouts. Each S pass evaluates four sampled paths for every factual node, so the bound corresponds to 72,000 TRAIN and 72,000 SELECT full-graph sampled-path evaluations. Construct and store path inputs once under the fixed public convention; separately charge their build/storage cost and any prospective scalar calibration. Calibration and prior native SELECT costs are not included in the optimizer bound and cannot be represented as a known end-to-end cost yet.

The lifetime cost is not zero for frozen F. E1 records the three reused F acquisitions as 1,558 backwards/Adam steps, 6,232 TRAIN route trajectories, 71.676 seconds summed acquisition, 0.0566 seconds restore and 0.5404 seconds selected readout; each deployed F bank has 216,674 served parameters. These measured historical scopes are not a wall-time estimate for the future path system. Across the **whole screen plus reused F**, the update maximum is 19,558 and TRAIN trajectory count is 24,232 (native route and complete path-predictor trajectories have different work per trajectory). Across the **candidate F+S alone** over three blocks, the bound is 4,558 backwards and 9,232 such TRAIN trajectories, with up to 3,000 new SELECT path passes. Path optimizer/build/qualification/calibration time, state size and full lifetime SELECT cost remain unmeasured; prior complete preparation/qualification cost was unavailable in E1.

For deployment, charge **four native-route forwards plus one full S forward** for F+S; one S forward for S alone; four independently parameterized S forwards for I4; and four native plus four S forwards for F+I4. A full S forward itself processes four three-position input paths plus disclosed raw/topology branches. F+S stores 216,674 native parameters plus all S parameters, path indices and branch state; F+I4 stores the native bank plus four complete S bodies. The native outputs can be cached once per block for fixed-graph development readouts, so readout reuse adds no native fits. That cache is not an inference-cost saving for fresh deployment graphs/features. No speed/storage saving is asserted.

On the representative full WikiCS graph (N=11,701, D=300), P=4/L=3/H=128 imply path-index storage `8*N*P*L` bytes (about 1.12 MB) and an ordered hidden buffer `4*N*P*L*H` bytes (about 71.9 MB), before tapes, raw/topology components and optimizer state. Source-backed path construction/feature similarities, sparse adjacency processing and per-node coefficients are separately charged. No N×N dense similarity/dictionary or edge×edge enumeration is required. Actual source/provider/role compatibility, parameter counts and full-graph memory/timing remain unqualified; root may decline the diagnostic without a rescue grid.
