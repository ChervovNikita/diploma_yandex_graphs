# Common saved-logit calibration and evaluation core

Source preparation only. `core.py` implements the common frozen DBLP/ACM scalar calibration, saved-logit metrics and complete-family paired summary. It has no dataset, label-file, checkpoint, graph or model reader, no inference or retraining, and no execution or label-release authority. Root retains selected-predictor and storage custody, label access, membership checks, final evaluation release and scientific admission. The common rule follows the root instruction and the adopted ACM scientific record SHA256 `96062ebf89e676d000c62f6a0ec577b8ec59a845196b98e08328bf6c3dcc1c24`, which explicitly reuses the frozen DBLP80-iteration rule.

`aggregate_logits(raw_logits, classes)` accepts FP32 native logits `[N,C]` or member logits `[M,N,C]`. The served ensemble is exactly FP32 `raw_logits.mean(0)` before any conversion; native logits remain unchanged. `selected_logits` maps explicit saved-row IDs to explicit requested IDs and aligns compact int64 labels with requested order. It rejects duplicate/missing IDs, nonfinite logits, wrong dimensions and labels outside the supplied fixed contiguous class schema. This supports both whole-target ensemble files and compact native validation files without inferring row IDs or classes from labels.

`fit_inverse_temperature(raw_logits, row_ids, validation_ids, validation_labels, classes, label_scope='SOURCE_VALIDATION_ONLY')` fits source validation only. It converts the served FP32 logits to FP64 and minimizes mean multiclass CE after multiplication by a positive inverse temperature on `[0.05,20]`. There are exactly80 golden-section iterations with no convergence stop or tolerance retuning. Equal interior objectives take the left-bracket branch. Final candidates are declared in this order: scale1, original lower bound0.05, original upper bound20, final left interior, final right interior. Selection uses strict score improvement, retaining the first minimum. Scale1 is therefore retained on a flat objective. The result records the candidate list, configured/completed iterations, fitted scale/temperature and raw FP64 calibration-reference NLL. A calibration failure retains its reason and falls back to scale1. It does not change the checkpoint selector, training loss, selected state or raw aggregation.

`evaluate_logits(..., calibration=fit_record, evaluation_scope='source_validation'|'heldout')` accepts labels already supplied under root custody. `raw.NLL_FP32` uses the existing FP32 `torch.nn.functional.cross_entropy` arithmetic directly. `raw.NLL_FP64_calibration_reference` is reported separately, and `calibrated.NLL_FP64` uses the fitted scale. Brier and ECE use FP64 softmax probabilities after FP32 aggregation: Brier is the per-node sum of class squared errors averaged over nodes; ECE uses15 equal-width max-confidence bins, left-closed/right-open except the last bin includes1. Predictions use logit argmax, preserving the configured predictor even when rounded softmax probabilities tie. Micro-F1 is accuracy; macro-F1 averages every fixed class, using0 for a class with no true or predicted instances. Positive scalar calibration preserves prediction order. No mean-probability aggregation is substituted.

`paired_summary(rows, family_binding, reference_arm='CP')` accepts complete evaluation rows with `arm`, `seed`, `status='complete'`, the exact same `family_binding`, and the output `metrics` from `evaluate_logits`. The root-owned binding must declare one dataset and evaluation scope, its fixed class schema (DBLP4 or ACM3), the full frozen arm list, all seeds `[131,137,139,149,151]`, `immutable=true`, and SHA256 fields `family_freeze_sha256`, `evaluation_manifest_sha256`, `predictor_lock_sha256`. The root verifies these actual immutable artifacts externally; this core verifies supplied binding equality and complete arm/seed membership. Do not trim the frozen arm list after outcomes. Missing, duplicate, failed, changed-binding or nonfinite rows return an incomplete record with no successful-subset scores. Each metric gets all five arm vectors and reference-minus-control vectors, mean, paired sample SD/SE, illustrative t95 interval, sign counts and five leave-one-block-out means in frozen seed order. Calibration fallback reasons remain in the complete summary. These quantities are descriptive seed uncertainty; they make no significance, power or independent-dataset claim and implement no practical acceptance threshold.

`qualification.py` contains one meaningful deterministic CPU `qualify()` function. It checks flat-objective first-minimum ties; perfect/bad fits at the upper/lower boundary; nonfinite and forbidden-scope failures; explicit ID mapping; FP32 mean-logit versus mean-probability aggregation; FP32 raw/separate FP64 NLL; logit argmax despite rounded-softmax ties; exact Brier/ECE confidence1 behavior and fixed-class F1; complete/allfive closure. It uses fabricated tensors only and no models or real labels. Local Python has no Torch module, so this numerical function is **unrun** here. Torch was not installed. Root may run the one function in the already authorized server runtime, for example `OMP_NUM_THREADS=1 python qualification.py` from this directory. The source is syntax-checked; numerical qualification and independent source review remain pending. Existing graph/model equivalence suites need no repeat for this core.
