# Member count and the private-learning partition

## Finding

**The current capable-single contrast does not isolate member count.** It is a useful strong quality/generic-adaptation comparison, with a disclosed optimization-partition difference. In transfer cells, F4 trains the encoder **and dense head bases** through the outer loss; capable_single trains only the encoder there and commits its entire nonlinear head from the inner loss. Moving roughly460,801 dense head parameters between these roles changes which labels update them, the mixed derivative, Adam histories and adaptation capacity. A positive F4–single difference can therefore reflect partition/capacity regularization. The live-minus-detached difference of differences against that single has the same limitation.

This agrees with the eight-family synthesis and finite-sample theory: a strong single can reproduce a useful sharing/shrinkage bias, and neither parameter counts nor a correct meta-gradient establishes ensemble necessity. The saved source release and cohort memos deliberately rejected a restricted factor-only F1 as the **sole** competent baseline. That protects the quality comparison; it does not make the chosen single a partition-matched intervention.

## Exact roles in the current code

| Arm | Outer block in live/detached transfer | Privately committed inner block |
| --- | --- | --- |
| shared_f4 | `encoder.*` plus every FactorLinear dense `weight`/`bias` in predictor `xlin`, `xcnlin`, `xijlin`, `lin` | Four rows of each linear `r`/`s`, five LayerNorm affine weight/bias pairs, and `predictor.beta` |
| capable_single | `encoder.*` only | All native nonlinear predictor parameters: every dense weight/bias, LayerNorm affine weight/bias and beta; no fast-factor r/s |
| Proposed F1 companion | The identical encoder and FactorLinear dense weights/biases as F4 | Exactly one corresponding F4 row of r/s, LayerNorm affine parameters and beta |

The eight FactorLinear locations are `xlin.ops.{0,3}`, `xcnlin.ops.{0,3}`, `xijlin.ops.0`, and `lin.ops.{0,4,8}`. The five private LayerNorm locations are `xlin.ops.4`, `xcnlin.ops.4`, `xijlin.ops.1`, and `lin.ops.{1,5}`. Dense biases stay outer in F4/F1; the norms' biases stay private. Encoder trainable names are `encoder.jkparams`, `encoder.xemb.1.weight` and `.bias`; native graph/buffer operations retain their original roles.

Constructor-shape arithmetic gives948,225 encoder parameters,460,801 dense head bases/biases, and6,402 private scalars per factor row (3,841 r/s +2,560 norm-affine +1 beta). F4 has1,409,026 outer and25,608 private parameters; proposed F1 has the same1,409,026 outer and6,402 private; capable_single has948,225 outer and463,362 private. These counts were derived from source without constructing a model.

`episode_step` commits one outer native Adam update, discards virtual private parameters/moments, recomputes inner gradients from original private state at the updated outer state, then commits private Adam once. Outer labels never directly commit the private block. Live credit includes the derivative through that private update; detached credit removes it. Ordinary-joint cells instead use all parameters jointly in the existing three-update paid schedule, so the transfer-role table does not describe their update allocation.

## One companion design, prospectively fixed

**Recommend one row0 F1 using four explicit inner forwards.** This is an additional companion, preserving the capable_single and all thirty original jobs, selectors, schedules and promotion gates. No implementation or execution is admitted by this report.

1. **Exact initialization and function.** Construct the same encoder and full existing unframed F4 bank under each block's original seed/factor_seed and original RNG fork, then slice/clone private row0 using the already present `select_bank_route` logic. Set one served member and use the existing `score_bank`/Route operations. Do not initialize a fresh one-row bank: changing factor-tensor shape changes generator consumption and subsequent factor values. Do not replace signs by ones, select a favorable row, absorb factors into bases, average bases or collapse nonlinear layers. Every encoder/base/bias tensor must equal its F4 counterpart and every private tensor equal F4 row0. Initial complete logits must equal **F4 route0**, not F4's generally different four-route mean.
2. **Identical parameter roles.** Derive private IDs after slicing. Only row0 r/s, norm-affine and beta are private; all encoder/dense head bases and dense biases are outer. Both blocks start with fresh native outer Adam and zero private Adam history; no qualifier/fitted state is donated.
3. **Four streams into one update.** On the same masked support, call route0 separately on each existing inner positive/negative query stream j=0..3, using dropout stream j. Compute the arithmetic mean of their four own normalized losses and differentiate it into the **one** private block, then make one virtual Adam update. Recompute all four losses at the new outer state with the same replayed masks, average again, and advance every stream exactly once during that recomputation. Do not take four sequential optimizer steps. Retain repeated sampled edges. Native Adam constants, zero-history branch and outer-dropout-off objective/serving stay unchanged.
4. **Why this differs from concat.** The frozen capable single concatenates four streams in one forward, using dropout stream0 and one union-normalized loss. Equal-sized concatenation has the same loss weighting in deterministic arithmetic, but shares one encoder realization, consumes differently shaped masks and pays one inner forward. The recommended F1 pays four differently masked forwards, matching F4's inner forward/encoder work and stream advancement more closely. This is the selected companion construction; concat is not an alternative to tune. Never multiply the averaged loss by four to assume Adam scaling cancels: epsilon and moment history make that assumption unsafe.
5. **Frozen task recipe.** Use the original blocks' seeds/factor seeds, full native TRAIN banks and permutations, 64 outer/256 inner queries per stream, endpoint eligibility, exact positive/negative target removal, 61 episodes including the tail, native dropout rates, and committed-state serving without adaptation. Keep sixty complete cycles, complete VALID every5, eleven misses, and the first maximum complete MRR rounded to four decimals. TEST remains closed. Reuse the original controls without changing their jobs or reopening partial scores.

This removes the dense-head role relocation. It does **not** make F4 and F1 identical function classes or optimization trajectories: four private rows versus one, their separate versus averaged gradients, the pooled/member outer objective and its Jensen term, and ensemble serving are inherent remaining differences. It tests the four-route mechanism under a matched role/stream recipe, not averaging in isolation or a universal need for ensembling. Initial equality to route0 also does not imply equality to the pool.

## Minimum meaningful admission and comparison

Before any later fit, extend the existing finite discarded TRAIN-only FP32 gate with F1 and route0 initialization/complete-logit parity; preserve the existing three architecture checks in the fresh exact-source gate. Current `run.admissible` binds both source hash and the exact three-architecture set, so the old result cannot silently admit new source/arm bytes. Keep the same zero plus two reachable private-moment histories, native parameter/moment parity, all-coordinate independent direct-plus-mixed derivative check, live/detached adapted-value parity, same-mask recomputed commitment, complete committed serving and native sparse alias/mode/RNG restoration. Specifically gate all four query/mask replays, one mean-gradient private update and one advancement per stream, including no unintended persistent outer-to-private gradient. Retain the current parameter/moment/derivative tolerances; no finite-difference or tolerance substitution. One full discarded TRAIN cycle can supply the necessary cost/resource bound before prospective release. This is design of the existing gate's minimal extension, not a new protocol framework.

The smallest useful complete companion study is **nine new fits**: row0 F1 endpoint/live, endpoint/detached, and endpoint/ordinary-joint, each in all three original paired blocks. Compare them with the corresponding frozen F4 cells after the original thirty fits and all nine companions are authenticated complete. Live/detached pairs test the learning-credit interaction under the matched partition; ordinary joint supplies a competent same-operation optimization reference. Do not run only the favorable rule/seed, alter the original promotion gate, or claim fresh heldout confirmation from this same graph. A claim that endpoint construction uniquely benefits the four-member learning credit would additionally require prospectively fixed F1 random/live and random/detached in three blocks (six more fits); the nine-fit companion alone does not identify that three-way interaction.

Keep the rich capable-single arms: they guard against winning through a deliberately small private adaptation class and remain the stronger generic-learning/quality alternative. F4 beating only the new F1 supports no claim of superiority over a capable single; F4 beating the capable single without the matched F1 remains partition-confounded. Fresh graphs/splits and competent contemporary references are still needed for method confirmation.
