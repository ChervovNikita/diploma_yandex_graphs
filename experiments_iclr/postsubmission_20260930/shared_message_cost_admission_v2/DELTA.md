# Metadata-helper v2 delta

V1 is preserved and remains unexecuted. Its suffix filter would reject four
legitimate paths in the exact pinned source closure: three PyG `.jinja`
templates and one provenance `.log`. V2 permits these suffixes while checking
every path and exact SHA against the same immutable scientific bindings.
No dataset, checkpoint, model, target or additional provider path is admitted.

The named lifecycle has four full byte-hash passes because the scientific
contract caches hashes by unchanged path/stat signature within a process.
Five audit calls still parse 45,000 epoch JSONs and 150 FIT_END files. V2
retains four full-byte metadata hash passes and additionally measures 18,060
cached-reference path/stat proxy checks (two extra traversals per metadata
file) to charge filesystem work even when bytes are cached.

The report field now says logical regular-file bytes. It is not allocated disk
and excludes later report/manifest and supervisor files. Root must obtain a
separate final scoped disk receipt, count filesystem allocation and all
supervisor outputs, and add a conservative reserve before scientific admission.
The helper's 256 MiB cap remains a logical output-file cap, not an OS quota.

Scientific models, quality source, runner v2, study matrix, recipe, labels,
thresholds and outcomes are unchanged. This packet remains source-only until
root authorizes a separate request and verifies successful bounded execution.
