## Source-resolved behavior

| Question | Exact source observation |
|---|---|
| Action parameterization | `models/CoGNN.py` constructs separate receive and send `ActionNet`s, each outputting two logits. Their independent binary samples form four communication states. This is a factorized implementation of the paper's four-action description, not a verified unrestricted four-way categorical sampler. |
| Sampling and ST gradient | `F.gumbel_softmax(..., hard=True)` is called for both policies at every layer. Torch2.0 source samples Gumbels via exponential draws and returns `hard-soft.detach()+soft`. Backward is the soft surrogate, not the derivative of a discrete action or an unbiased policy gradient. |
| Temperature | One temperature model per CoGNN is reused across depth and both policies; it returns `1/(softplus(linear(x))+tau0)`. With positive scalar temperature, changing temperature does not change the ideal hard argmax of logits+noise; it changes the ST backward surrogate. Floating-point saturation is still possible. The source uses the library sampler, not the saved paper's incorrectly signed printed density. |
| Train versus inference | Sampling is unconditional in `forward`; `.eval()` disables dropout but **does not disable Gumbel sampling**. The runner makes a fresh single forward for each role, rather than deterministic argmax or Monte Carlo averaging. |
| Sharing across depth | Receive net, send net, temperature model and optional hidden LayerNorm are constructed once outside the environment loop. Environment layers have separate modules/weights. |
| Edge direction | For stored source `u` and destination `v`, `edge_weight=receive[v]*send[u]`. Original edge indices are retained; zero weights suppress messages without deleting their autograd path. |
| Mean normalization | `WeightedGNNConv` multiplies each message by the gate, then uses ordinary mean aggregation over **all listed edges**, including zero-weight ones. The PyG2.3 scatter implementation divides by original edge count, not sum of gate weights. Recipient gradients therefore are not normalized away. Sum aggregation has no denominator. |
| Empty neighborhoods | Weighted Sum/Mean aggregation produces a zero neighbor vector for an empty row; the layer still applies a learned map to concatenated own state and neighbor vector. When all existing messages are zero-gated, the same own-state route remains. This is a source inference, not an executed fixture. |
| Other operators | The snapshot's `ModelType` supports SUM/MEAN/GCN/GIN/LIN. It has no native GAT dispatch. WeightedGCN uses gated `gcn_norm` and added loops; it is a different normalization path, not the MeanGNN guarantee. |
| One-layer policy size | With one MeanGNN policy layer, `act_dim` is unused: the sole map takes `[x,mean_neighbors(x)]` directly to two logits. Two binary policies at widthD contain `8D+4` parameters; a linear learned temperature adds D. At D512 this is4,612/member,18,448 for four, before any added normalizer. These are derived parameter counts, not measured memory/cost. |

## Native runner and competence limits

The runner uses masked TRAIN loss and Adam, but evaluates TRAIN/VALID/TEST every epoch. Its evaluation **loss** uses complete supplied targets, whereas its reported metric masks the requested role. It records best validation-associated metrics without saving/restoring best model weights; final edge statistics use the final model. There is no `no_grad` wrapper in the inspected evaluation function. These semantics cannot be copied into the project as an exact TEST-free selected-state runner.

The repository includes CLI defaults and a three-layer/width64 Roman-Empire example; neither is a recovered winning configuration for the paper's benchmark table. The saved paper hyperparameter ranges likewise do not identify a uniquely competent recipe. A source-linked runnable configuration is not a competence certificate. Future evaluation needs our role-bound TRAIN/VALID projection, full actual checkpoint+optimizer custody, strict first-best selection, policy RNG custody and serving defined before outcomes. This deliberately changes the runner, and must not be called an author-result reproduction.

Native regression is **RootNeighbours only**, not ZINC. The source creates1000 components, each with disjoint TRAIN/VALID/TEST trees and one supervised root per role:1000 roots/role. Each root has five target components equal to the mean features of its degree6 hub neighbors. TRAIN has1–3 hubs, while evaluation trees add2. Features are sampled in[-2,2). Training loss is MSE; selection/reporting metric is MAE. The degree rule provides an exact structural oracle for the constructed task. It can check an operator or planted mechanism, **not real-task superiority, a contemporary molecular benchmark, or a need for four members**. No generator was executed or target payload read.

PyG's ZINC source documents the predefined12,000-graph benchmark subset, separate train/val/test index files, categorical atom and bond inputs, and a scalar penalized-logP target. The checked provider documentation also distinguishes ZINC-full. The inspected source/documents do not establish a CoGNN recipe or independently verify the usual10k/1k/1k cardinality breakdown; a future role manifest must bind exact counts and provider identities. No archive, index array, molecule, label or TEST payload was acquired. Stock PyG processing traverses all three roles, so a separately reviewed TRAIN/VALID-only exporter is required for project use.
