# Stored-state equality and its limits

The CPU comparison examines four original Squirrel17 post-install snapshots: `common_only`, `selected_graph_pair`, `selected_permuted_span`, and `selected_random_span`. The saved TRAIN-only structure says all four return the common head: graph and permuted selectors abstain; random has no eligible pair. The fixed graph-pair arm is a distinct start and is excluded from the common-start comparison.

## What is actually preserved

The installation archive contains the actual selector-input prototype's registered model-state tensors, one frozen named-Adam snapshot, one native continuation RNG snapshot, module mode flags, and each installation's intended head slices/full registered model state/modes. Its original return custody receipt observes that every returned optimizer, RNG and mode inventory equals those shared frozen inputs, and that each returned head equals its own intended installation. The per-arm optimizers and RNG are not saved as separate live objects. The native warm archive and logical fingerprints bind the original warm model/Adam/RNG. The comparison does not restore those objects.

The frozen Adam snapshot records canonical parameter names, all registered parameter aliases, shapes, `requires_grad`, group order/options, steps and moments. Restoration source checks alias inventory and covers every registered parameter. Saved CPU tensor copies preserve values rather than original device/storage identity. Equal values under several alias names do not independently reconstruct live pointer links. Original live-custody/storage checks remain separate historical observations.

The captured input is bound by its complete saved-file hash and the original preprocessing/warm logical-reference chain. The CPU task hashes that file and compares saved descriptors without loading its tensor payload, recomputing preprocessing or opening label packs. It does not recompute the logical input fingerprint from the tensor itself.

## Forward-relevant state that was not captured per installed model

1. **Unregistered tensor.** In the bound `native_polyformer.py`, `PolyAttn.bias` is assigned a plain `torch.tensor` without `register_buffer` or `nn.Parameter`. The forward uses it in `attn_mask`. It is absent from `state_dict`; its actual per-install values were not witnessed.
2. **Architecture and scalar configuration.** Wrapper/projector `members`; `core.K`, dropout and layer/module order; attention `K`, `n_head`, `d_head`, `dprate`; FFN dropout and module-specific activation/normalization configuration are not serialized by the state comparison. Source also has `base`, `multi`, dataset and layer-count constructor attributes. Some influence construction or bookkeeping rather than a direct forward read. Native warm specification and the bound constructor describe intended settings; they are not a snapshot of every installed object's actual fields.
3. **Nonparameter aliases and runtime links.** Shared module objects, buffer storage links, optimizer-to-live-parameter links, Python class/type hierarchy, replaced boundary ownership, tensor device/stride/layout, `state_dict` metadata and nonpersistent buffers are not fully represented by detached CPU values. Registered parameter aliases and `requires_grad` are present in the shared named-Adam inventory, with original restoration/live-custody evidence, but not fresh per-arm pointer observations in this task.
4. **Hooks and execution behavior.** Per-module forward/backward/state hooks, monkey-patched or compiled callables, other unregistered attributes/caches, per-object RNG generators and backend execution state were not captured. Saved global Python/NumPy/Torch CPU/CUDA RNG states do not establish equality of arbitrary custom generators or separately repeated backend trajectories.
5. **Continuation context.** Graph object fields such as class count, scientific callbacks, TRAIN/VALIDATION node and label packs, source selection/stopping context and all per-parameter `.grad` fields are not independently checked by this label-free comparison. The bound continuation clears gradients before its update and has no arm-name input, but this task executes neither behavior. Module `training` flags are captured and compared; they are not missing state.

The selector source deep-copies the same prototype for each arm and only changes the chosen head slices. It then restores the same frozen named Adam, modes and native RNG. This supplies a strong construction argument for common/null starts sharing these other fields, including the unregistered bias. This CPU task does not replace that argument with a full live-object equivalence observation.

## Decision supported by the null

The selected graph initializer abstained in a required Squirrel17 block. Its intended selected-head intervention is therefore absent relative to common, permuted and random starts. The frozen mechanism screen requires a favorable paired NLL sign in every seed against every control; this null start cannot provide evidence for that intervention. Backend variation or an unsaved-field discrepancy cannot establish the intended mechanism.

Close this selector version as a structural no-intervention result with recorded limits. Thirty additional continuations are unnecessary to discover the missing intervention. This is not a measured NLL tie, an accuracy comparison, proof that repeated native trajectories are bitwise equal, a failure of GNNM in general, or a revised screen. It does not qualify the method or alter original paper results. Preserve the distinct fixed-pair mismatch and warm/preprocessing repeatability records without further repair in this task.
