# All COMMON competitors: separate CPU analysis adapter

Source preparation only. No scientific prediction archive, checkpoint, model,
graph or labels were opened here. Four artificial-probability counterexamples
validate the logical distinctions; they are not scientific results.

Root calls `adapter.run(output, collection)` after the existing whole9 collection
is complete. It requires every fixed seed8101/8203/8307 and condition
shared_common/shared_route/shared_route_permuted, original owner/children terminal
custody and the frozen family-target identity. All nine raw prediction bindings
are verified before any semantic array read. Complete5274 IDs/labels, M4 and ten
classes are retained, including exact paired role identity across seeds.

The adapter opens only five existing prediction fields from each already-created
archive. It builds the complete wrong-class set from COMMON alone before this
adapter reads candidate arrays. This does not assert a new chronology for the
earlier collector: the fixed rule is prepared before research readout, and the
original COMMON error cohorts were frozen by the existing collector. No candidate
result selects the classes. Raw arrays remain server-only.

For a COMMON node, a qualifying rival is a same nontruth class strictly above
truth in every original member. Retain ALL such classes. Count separately:

- one SAME candidate member strictly beats ALL old rivals;
- each rival is beaten by some potentially different member;
- actual candidate member correctness under native argmax;
- actual pooled repairs, introduced errors and newly common rivals;
- repairs without one member beating all rivals, including all-member-wrong
  cases rescued by the pool; and per-member repairs/introduced errors.

Beating all baseline rivals is not sufficient for correctness: a new rival can
block truth. It is not necessary for a convex pool to repair: different members
can reverse different rivals and their mean probability can favor truth even
when every member's top prediction is wrong. Per-rival reversal is itself
insufficient if wrong-class confidence still dominates the average. Strict
reversal also differs from ordinary argmax at ties. The saved synthetic examples
cover all four distinctions with ten classes and four members.

Use the stored native pool predictions; do not replace them with a recomputed
softmax or impose a microscopic floating-point invariant. Report any COMMON
competitor/pool-correct coincidence as a diagnostic. Counts on class-node pairs
and repeated seed-node instances are descriptive, not independent observations.

The output is `compact/ALL_COMMON_COMPETITOR_DIAGNOSTICS.json`. It adds no model,
forward, fit, input-dataset or inference call; it changes no frozen gate, optimizer
or sealed readout/training source and authorizes no scientific execution. Root's
existing immutable collection/custody admission remains the prerequisite. A
passing logical check establishes no competence, quality, novelty or acceptance.
