### Reconstruction leakage precautions

`mask_block` samples a uniform permutation of eligible non-TRAIN nonzero-feature rows using an isolated CPU generator, takes half rounded down to a multiple of four, partitions its randomly ordered sample into equal quarters, clones raw X, and zeros every selected complete feature row (`method.py:110–118`). Only the resulting Xmask is passed to the frozen donor encoding (`run.py:27–29`). The donor is frozen, forced to evaluation mode, and encoded under `no_grad` (`method.py:35–39, 60–67`).

Only Xmask, Hmask and edge_index enter each private graph path. `ssl_representation` refuses an existing clean cache, and the clean cache is first created after all SSL updates and decoder/optimizer disposal (`method.py:69–71`; `run.py:41–46`). All S latent rows are then set to zero before sparse decoder propagation (`method.py:96–108`). Raw target features occur solely in the cosine loss indexing (`method.py:134–143`). No clean H0, clean z0, teacher prediction, pseudo-label, or class-conditioned mask enters reconstruction. Masked logits are computed by the native interface and immediately discarded; they are not a teacher input (`run.py:28`).

The graph representation of an unmasked node can contain masked-node context propagated by the masked frozen backbone and private graph path. That is legitimate graph context: the raw target row was already removed from the entire encoding input. The frozen donor itself was acquired in the normal transductive setting, so this is not a claim that the donor has never encountered these public features.

### Targets, gradients, and mathematical meaning

Each decoder computes `affine(A_norm @ Remask(R_m,S))`, with incoming degree normalization and self-loop coverage check. This matches the stated `D^-1/2 A D^-1/2` graph decoder for the prescribed symmetric prepared graph (`method.py:96–108`). The exact graph support is trusted through the pinned payload; the loader does not independently prove symmetry or exact one-self-loop structure. The target-row normalization excludes zero raw rows; reconstructed zero vectors use cosine epsilon1e-8, rather than producing division by zero.

For BR, every branch sees quarters `[0,1,2,3]`. BC and SC use `[0,1,2,3]`, `[1,2,3,0]`, `[2,3,0,1]`, and `[3,0,1,2]`. Thus each branch sees every S row once per block in all conditions, every update has |S|/4 targets per branch, and every S row contributes four times per block over the four branches. Concurrent coverage differs. At fixed parameter values, the sum of the four update objectives is the same full-S per-branch objective; the gradients encountered during optimization differ because parameters and Adam moments change between quarters. Matching is target cardinality and block coverage, not equal instantaneous gradients or equal trajectories.

The loss is the mean of four branch means of `(1-cosine)^2`. Each path and decoder therefore receives its own branch gradient with factor1/4. A single AdamW owns all four paths and all four decoders, but there is no shared trainable backbone, cross-branch loss, gradient clipping, or other cross-branch term. The optimizer decomposes by parameter. BC versus BR primarily changes cyclic within-block order in paths1–3; path0 has the same schedule in both. Complementary synchronization alone is not a training interaction. The source and NOTE correctly frame the question as synchronization/order with equal population objectives, not persistent semantic specialization (`NOTE.md:24–27`). This source review does not assume either schedule is useful.

All four graph paths and all four reconstruction heads are in the SSL optimizer, all receive autograd gradients, the active parameter/gradient tensors are checked finite, and class heads remain zero, frozen, and without gradients (`method.py:120–158`). Class fitting starts with a new source Adam and no SSL moment state. Zero graph gradients can still be finite; the check guarantees connectivity and finiteness, not nonzero or useful signal. The initially zero class heads imply zero graph gradient on the first class step by construction, while the heads can learn.

### Candidate versus capable single and stochastic matching

Both families construct the same four isolated original GraphPaths at `seed+1009*m`, including the discarded original zero-output heads for singles. The original graph source includes a 300→512 raw affine, native-style GAT local block, layer norm and beta, and private dropout0.5 (original `method.py:102–142`). The single adds an unrestricted affine2048→10 residual classifier on all four concatenated representations. The bank has four affine512→10 residual classifiers and serves mean probabilities. Counts are 20,490 versus20,520, a disclosed30-parameter difference (`method.py:35–57, 72–94`). Four genuine paths are trained and served by the single; there is no dummy padding or one-path shortcut.

BC and SC have the same four paths, same isolated decoder construction seed, same isolated mask seed, no SSL dropout, same branch assignments, same loss, and the same optimizer parameter sequence. They have the same intended mathematical SSL state before classification on one matched device/runtime. No bitwise reference-parity claim or extra parity run is necessary here. Construction and SSL restore global RNG snapshots; SSL evaluation consumes none of the stored classification dropout streams (`method.py:120–125, 135`; original `method.py:27–44, 135–142`). Classification forwards route the same per-path streams in every arm, each for100 updates (`method.py:72–89`; `run.py:55–73`).

The bank pays four staged100-update own-CE+2pool-Brier fits, caching three eval peers once per stage. The single pays100 joint updates with CE+2served-Brier, with each path receiving100 class updates. Thus active path-update count and SSL opportunity match. The losses, gradient scaling, temporal training order, probability function class, and optimizer-step totals differ; the affine joint single does not algebraically contain every mean-of-softmax bank. BC versus SC tests two capable matched-path procedures, not an isolated change in averaging. It cannot establish superiority over a fully trainable native single with the same SSL opportunity. The stated broader-claim limitation is necessary and present.

### Work and serving

The loops support25 masked frozen encodings,100 joint AdamW updates,400 private path forward/backward computations, and400 decoder forward/backward computations per SSL arm. NoSSL arms omit this work. Classification supports400 path forward/backward computations in either family, plus12 bank-only frozen peer forwards and one clean class encoding. Final serving pays one fresh clean backbone encoding and four private paths, with no decoder. Parameter arithmetic confirms153,900 per decoder,615,600 total, and23,963,648 bytes for one float32 Hmask. That tensor size is not peak memory. The runner also writes initial/final model snapshots and the discarded decoder/optimizer snapshot, so those storage and serialization costs are real (`run.py:21, 41–43, 77–88`). The stream contains dropout states for custody; serving does not use them.

The main work counters are structurally justified. They are forward/backward operation counts, not time-equivalence or speedup estimates. The source child timings and resources have the coverage limits in launch gate3. The external owner function and helper bytes match their GPU77 provider bindings; importing that function does not automatically establish a sealed SSL adapter or authorize a launch.

## Limitations that do not block this bounded source release

- Static source and JSON/AST/arithmetic inspection cannot establish numerical execution, runtime feasibility, memory peaks, donor competence, useful gradients, or accuracy. No ML framework was imported, no dataset or checkpoint payload was opened, and no GPU or remote work occurred.
- The full source manifest's49 entries and all three input bindings matched their hashes and lengths. That proves this review's byte identity, not the authority of actual future root jobs or the meaning of their external receipts. Exact hashes are recorded in SOURCE_BINDINGS.json.
- Reported SSL `active_private_gradient_norm` includes decoder parameters as well as paths; class `active_gradient_norm` includes class heads and the combined CE+Brier objective. These norms cannot by themselves establish that useful CE gradients on the private graph paths have vanished. Small donor TRAIN CE also cannot prove that premise. No extra gradient diagnostics or diagnostic training is required; interpretation must respect what these aggregate norms measure.
- Score.py emits accuracy, NLL and multiclass Brier, plus saved member/pool probabilities. It does not emit a separately defined calibration statistic, common-wrong overlap, disagreement, or a cross-arm reconstruction comparison on a common diagnostic target set. Those are optional development diagnostics, with no endpoint tuning or extra fit permitted. Training reconstruction curves use each arm's assigned targets and evolving parameters, so they are not a common held reconstruction evaluation.
- Three seeds on one selected WikiCS split form a small development population. “Matches” needs a stated descriptive/statistical meaning; lack of an observed gain is not an equivalence proof, and node outcomes are dependent within the graph. Report all prescribed paired arm results. Fresh task/population confirmation and a native single with the same SSL opportunity are required for broader claims.
- Once-only execution, successful-terminal custody, and exact pairwise arm matching are partly root responsibilities, as described in the launch gates. The child guards are meaningful fail-closed role/source checks, but they are not a complete independent supervisor.
- Masks may emphasize nuisance features or be ineffective with a frozen classification donor. Reconstruction, gradient norm, disagreement, or member competence does not substitute for complete served accuracy. GraphMAE-style ancestry and shared/private ensemble ancestry remain relevant; originality is not established.
